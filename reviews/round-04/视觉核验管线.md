## 0. 双套核验标准（用户 2026-09-09 口述确立）

1. **脚本核验（第一层）**：编译通过（latexmk 零 error）、diff 存在且逐项对应修改点、
   pdftotext 文本层无源码残留（`latex`/`verbatim`/`needspace` 裸串）、编号引用配对。
2. **视觉核验（第二层）**：PDF 渲染成图后在"视觉"层面正确——文字无重叠、无截断、
   题注与图同页、表头单行、编号右对齐。最终交付物是视觉状态，以这一层为准。

本会话模型无图像输入通道，视觉核验通过**渲染 + OCR + 像素簇分析**三段式间接实现（见 §2）。
OCR 无法判定的残留盲区（截图内容完整性、颜色、图形美观）列入"待用户目验清单"，不得默认通过。

## 2. 三段式判定法

1. **OCR 坐标扫描**：两段文本 y 区间重叠 ≥60% 较小盒高度（严格共基线=同一行）且 x 区间
   交叠 > 25px@300dpi（约半个正文字宽）→ 重叠。T-052 实测校准：tikz 节点 `\\` 换行的上下
   堆叠行（图 1-1 双行白衬节点）、表格相邻列的 OCR 框外扩（表 1-1 实测 15-16px 级）均为
   合法排版不判重叠；真实挤压（表 6-2 历史）交叠远超阈值。
   表头/正文若出现 `latex`、`needspace` 等裸串 → 转换器 fence bug。
2. **像素簇验证**（OCR 聚合歧义时）：按行带做灰度垂直投影，相邻文字簇间隙 < 10px 视为接触。
3. **盲区登记**：OCR 文本为乱码/低置信（截图内部、图形）→ 记入"待用户目验清单"，
   在交付说明中单列页码，不得标 pass。

## 3. 每轮修改的标准流程

```
改 md/转换器 → python convert → latexmk -g
→ 第一层:grep 编译日志(0 error) + pdftotext 扫残留 + diff 对照修改点
→ 第二层:定位改动所在页 → pdftoppm 300dpi → ocr_tool 坐标扫描 → 疑点像素簇复核
→ 产出:两层各自的 pass/fail 清单(带页码) + 待目验清单
```

## 5. 盲区与限制

- OCR 对截图内部文字识别率低（斜体小字/界面图形），只能判"该图是否存在"，判不了内容对错；
- 颜色类问题（着色是否正确）完全不可判；
- `/tmp/vcheck/` 会被系统清理，ocr.swift 已回仓 `scripts/audit/vcheck/ocr.swift`（agent-work/
  scripts/vcheck/ 为同源副本），重建用 `sh scripts/audit/vcheck/ensure_ocr_tool.sh`。
