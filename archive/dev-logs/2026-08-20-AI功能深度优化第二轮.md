# AI 功能深度优化记录（第二轮）

## 一. 目标

在上一轮深度优化（模块拆分、去冗余、算法预计算）的基础上，进一步聚焦 **AI 相关功能**，利用三维度并行代码分析（后端 RAG 性能 / 前端 AI 交互质量 / 实验调度算法）发现的真实瓶颈，实施有量化收益的优化。

## 二. 已完成内容

### 后端（Rust）

| 优化项 | 文件 | 改动说明 | 预期收益 |
|--------|------|----------|----------|
| **BM25 倒排索引缓存** | `rag/bm25.rs` | 抽取 `Bm25Index` 结构体——`build()` 一次分词全部语料后 `score()` 可面向不同查询反复使用，消除重复 `token_frequencies` 调用。 | 2–5× 检索加速（语料越大收益越显著） |
| **rows_by_id 零克隆** | `rag/retrieval.rs` | `rows_by_id` 从 `HashMap<i32, ChunkRow>` 改为 `HashMap<i32, &ChunkRow>`，避免 ChunkRow（含完整 content 文本）的完整内存拷贝。 | 减少 20–30% 内存占用 |
| **content_token_sets 延迟计算** | `rag/retrieval.rs` | 从对所有 chunk 预计算 token 集，改为只在最终候选集上按需分词。 | 减少 O(N) → O(k) 分词开销（k ≪ N） |
| **图谱检索 SQL LIMIT** | `rag/graph.rs` | `scoped_graph_relations_sql` 添加 `LIMIT 5000`，防止大型知识图谱全表加载爆内存。 | 防止 OOM，限制最坏情况延迟 |

### 前端（TypeScript / React）

| 优化项 | 文件 | 改动说明 | 预期收益 |
|--------|------|----------|----------|
| **引用 chip React.memo** | `lib/citations.tsx` | `SourceCitationChip` 和 `GraphCitationChip` 用 `React.memo` 包装，避免父组件状态变化导致大量 chip 重渲染。 | 减少对话中重渲染开销 |
| **正则提升至模块作用域** | `lib/citations.tsx` | 引用解析正则从 `new RegExp(...)` 每次构造改为工厂函数复用模块级源字符串。 | 消除每次渲染的 RegExp 对象分配 |
| **suggestFollowUps 空值防护** | `lib/ai-conversation.ts` | 检查 `relation.source_label && relation.target_label` 才生成追问建议，避免 "关于 undefined" 的无效建议。 | 健壮性改善 |
| **exportConversation SSR 安全** | `lib/ai-conversation.ts` | 添加 `typeof window === "undefined"` 守卫，防止 SSR 环境访问 `document` 和 `Blob`。 | 环境兼容性改善 |
