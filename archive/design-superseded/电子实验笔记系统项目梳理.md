# 智能电子实验笔记系统项目梳理

> 按照《基于微服务器架构的慢阻肺数字化管理系统设计与实现》（魏潘晨）描述项目的组织方式，对本项目（智能电子实验笔记系统，ELN）进行系统梳理：项目概述 → 总体业务与角色 → 目标与解决的问题 → 需求分析 → 详细设计 → 系统特点 → 实现与测试 → 总结与展望。
> 文中内容均依据仓库代码与证据文件整理，标注了对应实现位置。

## 1. 项目概述

### 1.1 项目背景

科研人员在做毕业论文实验验证时，实验记录、原始资料、检索配置、模型参数、人工评价散落在本地文件、文档和记忆里，存在三个突出问题：一是实验过程不可追溯，同样的 RAG 配置换了环境就无法复现；二是资料与笔记的审核、版本、权限缺乏管控，谁改了什么、谁批准了什么没有记录；三是 AI 回答的准确性、可追溯性缺乏可验证的评价机制，"回答看起来像对的"不能作为通过条件。

### 1.2 项目目标

本项目旨在构建一套面向科研过程管理与论文实验验证的电子实验笔记系统（ELN），实现从"实验记录 → 资料审核 → 知识库构建 → AI 检索问答 → 成对对照实验 → 盲评验证"的完整闭环，核心业务包括：权限管理、审批流、实验笔记、资料库、OCR、知识图谱、本地 RAG、DeepSeek 问答、固定任务智能体和成对对照实验。

### 1.3 主要工作

1. **核心业务系统**：完成认证与 RBAC 权限、项目与成员管理、实验笔记（草稿/提交/审核/模板字段）、文件上传与 OCR、资料审核等核心闭环，任何 AI 功能都建立在核心业务之上（`backend/src/api/{auth,projects,notes,files,ocr}.rs`）。
2. **检索增强生成（RAG）**：实现文档解析分块、向量嵌入、pgvector 检索与 BM25 词法检索的混合排序、知识图谱关系注入，以及"纯 LLM、BM25 RAG、混合 RAG、结构化查询、图谱增强 RAG"五种可对照的检索模式（`backend/src/rag.rs`、`backend/src/api/rag.rs`）。
3. **AI 问答与智能体**：接入 DeepSeek 官方 OpenAI 兼容接口完成生成；实现六类固定任务智能体（实验总结、周报、阶段报告、图谱概览、文献综述、异常检测）和可规划、可调用工具、可等待人工确认的交互式智能体（`backend/src/api/agents.rs`、`backend/src/api/agent_runtime.rs`）。
4. **MCP 开放服务**：以 JSON-RPC 2.0 标准实现 Model Context Protocol 服务，对外提供 11 个工具（检索、图谱查询、草稿笔记、审核、重建索引等），带 scope、风险分级、幂等键与人工确认机制（`backend/src/api/mcp.rs`）。
5. **实验验证体系**：实现固定种子、随机运行顺序的五方法成对对照实验、provenance 全量落库、方法隐藏盲评、证据冻结与成熟度门禁，形成"内部自动证据 → 独立人工评审"两级验证体系。

### 1.4 主要创新点

1. **AI 真实性工程化**：生产环境强制真实嵌入模型（bge-m3/1024 维）与真实生成接口（DeepSeek），禁止用测试替身或模拟回答冒充；检索、生成、引用审计全程落库可追溯。
2. **引用契约与防幻觉**：回答必须携带 `[S]` 资料编号与 `[G]` 图谱编号，服务端逐条审计，缺失时自动修复，仍不满足则显式标记"需要人工复核"，不静默产出无依据内容。
3. **可复现实验设计**：实验运行顺序随机化并保存实际顺序与配置哈希，同种子可复现；语料快照哈希、模型版本、提示词版本、token 用量全部随记录导出。
4. **公平盲评机制**：评价人只看问题、回答与证据，看不到方法标签；两名独立评价人背对背评分，一致性用 Cohen's kappa 度量，负面判断强制填写依据。

## 2. 系统总体业务描述

系统围绕"项目"组织所有业务：科研人员创建项目 → 团队成员记录实验笔记（草稿→提交→审核）→ 上传实验资料（文件→OCR→审核入库）→ 审核通过的笔记与资料进入知识库与知识图谱 → 通过 AI 问答（五种模式）与固定任务智能体获取基于证据的分析 → 通过"论文对照实验"模块运行成对实验 → 由独立评价人盲评导出证据。

### 2.1 系统角色分析

| 角色 | 角色功能 |
| --- | --- |
| 超级管理员 | 系统全局管理：用户、群组、项目创建、系统配置审计、成熟度门禁查看 |
| 项目所有者（owner） | 项目全权管理：成员与权限分配、资料审核、索引重建、实验管理 |
| 项目审核人（reviewer） | 审核实验笔记与资料、参与盲评管理 |
| 项目成员（member/writer） | 撰写笔记、上传资料、发起实验、使用 AI 问答 |
| 观察者（viewer） | 只读访问项目数据 |
| 评价人（can_evaluate） | 仅能进行盲评打分，无数据读写权限（`evaluate_agent_quality` 要求 `can_read/can_write/can_review/can_manage` 均为 false） |

权限模型为细粒度 RBAC（`backend/src/permissions.rs`）：每个项目成员按"角色 + 五个布尔权限位（can_read/can_write/can_review/can_manage/can_evaluate）"授权，AI 相关操作全部经过权限校验。

## 3. 系统目标与解决的问题

### 3.1 系统目标

- **过程可追溯**：每一步（笔记提交、审核、资料入库、实验运行、评价打分）都有审计记录与 provenance 字段。
- **结果可复现**：冻结语料、冻结题集、固定种子，同配置重跑得到一致结果（`result_sha256` 校验）。
- **AI 可验证**：五方法对照、方法隐藏盲评、证据冻结，论文结论只能用真实接口运行数据支撑。
- **数据安全**：生产模式强制安全配置，敏感项目默认禁止向外部 AI 发送内容。

### 3.2 系统解决的问题

| 问题 | 解决方案 |
| --- | --- |
| 实验过程不可追溯 | 每条件问答记录模型、提示词版本、检索参数、来源块与相关度、图谱关系、耗时与 token（`rag.rs` 的 `insert_query_log`） |
| AI 效果无法评估 | 五方法对照实验 + 双评价人盲评 + kappa 一致性 + 完成门禁 |
| AI 回答不可信 | 引用审计、无证据拒答（"无项目证据"前缀）、强制图谱未命中报错、降级原因落库 |
| 证据可事后造假 | 证据冻结绑定 git commit、Cargo.lock、package-lock、镜像 digest，SHA-256 manifest 校验 |
| 评价不独立 | 评价人专用权限角色、方法标签中性化、负面判断强制备注 |

## 4. 需求分析

### 4.1 功能需求

| 模块 | 功能需求 |
| --- | --- |
| 认证与账号 | 注册/登录、JWT 会话、密码修改与重置、退出后旧令牌失效（`auth.rs`） |
| 项目管理 | 项目创建、成员管理（角色+权限位）、敏感项目标记、项目级审计（`projects.rs`） |
| 实验笔记 | 草稿/提交/审核状态机、模板与结构化字段校验、版本约束、跨项目权限（`notes.rs`） |
| 文件与 OCR | 上传（大小限制）、Tesseract 识别（中英 chi_sim+eng）、识别原文与校对文本分离、审核后文本才进 RAG（`files.rs`、`ocr.rs`） |
| 资料库与知识库 | 资料审核（approved 才可索引）、向量入库、索引重建、stale 标记（`rag.rs`） |
| AI 问答 | 五种模式（pure_llm/bm25_rag/project_rag/kg_enhanced_rag/structured_query）、多轮会话、引用渲染、失败显式报错（`api/rag.rs`） |
| 知识图谱 | 审核笔记自动抽取实体关系、图谱可视化、相关关系注入问答（`knowledge_graph.rs`） |
| 固定任务智能体 | 六类任务模板，基于已审核证据生成带引用编号的草稿，证据不足时明确"无法确认"（`agents.rs`） |
| 交互式智能体 | 会话/回合/工具步骤模型、计划预览与人工确认、工具风险分级、SSE 事件流（`agent_runtime.rs`） |
| MCP 服务 | 11 个工具、6 个提示模板、资源读写、PAT 令牌与 scope、幂等键、审计（`mcp.rs`） |
| 对照实验 | 题集管理、随机顺序运行、后台队列、中断显式续跑、CSV 成对导出（`api/rag.rs` 实验段） |
| 盲评 | 方法隐藏、双评价人、提交不可修改、汇总一致性校验（`api/rag.rs` 盲评段） |
| 系统管理 | 用户/群组管理、审计日志、运行指标、成熟度门禁状态（`api/maturity.rs`） |

### 4.2 非功能性需求

1. **安全性**：生产模式强制非默认密钥/密码、关闭演示数据；敏感项目禁止外发 AI；`SECRET_KEY` 轮换流程；反向代理 TLS 模板；npm audit；日志不打印密钥。
2. **可靠性**：`/health` 与 `/ready`（含数据库与存储检查）；一致性备份与恢复演练；监控告警探针（错误率、in-flight、p95）；实验中断恢复（`interrupted` 状态显式续跑）。
3. **性能**：`/metrics` 记录请求数、状态码分组、p95 延迟；90 并发/60 秒 soak smoke 验证；查询日志与索引覆盖查询。
4. **可复现性**：固定 Rust 1.88.0 工具链、锁文件、冻结语料与题集哈希、result_sha256 复现。
5. **易用性**：浏览器端到端流程可走通，前端页面提供模式说明、来源块与图谱上下文渲染、实验进度轮询。

## 5. 详细设计

### 5.1 技术架构

系统采用前后端分离的 B/S 架构，单进程后端：

| 层次 | 技术选型 |
| --- | --- |
| 前端 | Next.js + TypeScript，生产以 `next start` 运行，API 类型由 `backend/openapi.json` 生成 |
| 后端 | Rust 1.88 + Axum，认证/权限/业务/AI 全部单进程执行，响应头 `x-backend-runtime: axum` |
| 数据库 | PostgreSQL 16 + pgvector（向量检索）+ HNSW 索引 |
| AI 生成 | HTTPS 调用 DeepSeek 官方 OpenAI 兼容接口（重试 3 次、并发限流、流式 SSE） |
| AI 嵌入 | 生产 OpenAI-compatible bge-m3（1024 维）；开发/测试用 `rust-hash-512-v1` 显式替身，生产配置校验直接拒绝 |
| 部署 | Docker Compose 构建生产镜像，TLS 反向代理（nginx 模板） |

### 5.2 AI 架构

- **检索管线**：文本分块（块大小/重叠可配）→ 嵌入 → pgvector 入库 → 查询时向量候选（top-30）+ BM25 词法候选合并 → RRF 融合排序（精确词查询时词法加权）→ 相关度下限过滤 → 多样性选择（普通 6 块，集合型 12 块）→ 低召回时 LLM 查询改写。
- **图谱增强**：`auto` 模式按相关度阈值注入图谱关系，未命中显式降级并记录 `fallback_reason`；强制图谱模式未命中直接报错，不伪造图谱上下文。
- **生成**：五模式各有独立提示词版本；回答带引用标记，`audit_citations` 审计缺失时触发修复重写；纯 LLM 模式无证据必须回答"无项目证据"。
- **智能体**：固定任务智能体构建"已审核笔记 + 相关文件 + 图谱关系"证据上下文（18KB 预算，只持久化模型真实可见的证据编号）；交互式智能体复用 MCP 工具注册表，高风险工具等待人工确认，工具结果按"不可信数据"处理。

### 5.3 数据库设计

核心数据表（`backend/src/db.rs` 运行时 schema 校验覆盖）：

- **组织与权限**：`users`、`groups`、`projects`、`project_members`（角色+权限位）
- **业务**：`notes`（实验笔记）、`files`（资料）、`file_reviews`、`approval_requests`
- **AI 数据**：`rag_files`、`rag_chunks`（含向量，pgvector）、`kg_entities`、`kg_relations`、`ai_query_logs`（问答 provenance）、`ai_experiment_runs`、`ai_experiment_cases`
- **智能体**：`agent_sessions`、`agent_turns`、`agent_steps`、`agent_pending_actions`、`agent_events`、`agent_messages`、`agent_generation_runs`
- **MCP**：`mcp_personal_access_tokens`（哈希存储）、`tool_execution_keys`（幂等键）
- **审计**：`audit_logs`

## 6. 系统特点

1. **核心业务优先**：任何 AI 功能都建立在"笔记—审核—资料—权限"核心闭环之上，基础系统未稳定不投入炫技功能。
2. **AI 真实性可验证**：运行时指纹（`/metrics`）、故障注入报错、无模拟回答，检测协议见 `docs/ai-inspection-protocol-v1.md`。
3. **引用级可追溯**：`[S]`/`[G]` 编号逐条审计，回答中的每个关键结论都能回溯到来源块或图谱关系。
4. **实验公平性**：题集冻结、方法隐藏、双评价人、无案例删除、全部模式同预算对比。
5. **证据冻结机制**：门禁结果、实验报告、盲评 CSV 与 git revision、锁文件、镜像 digest 绑定。
6. **安全分级**：敏感项目默认禁止外发 AI、高风险智能体工具必须人工确认、PAT scope 最小授权。
7. **多协议开放**：REST API + SSE 流 + MCP JSON-RPC 三种对外接口。
8. **运维完备**：健康检查、指标、备份恢复演练、监控告警、TLS 部署预检。

## 7. 实现与测试

### 7.1 核心流程实现

1. **资料入库与知识库构建**：上传文件 → OCR/解析 → 审核 → 向量入库 → 查询（`scripts/import_gse111619_via_api.py` 演示了完整 API 流程）。
2. **AI 问答**：前端选择模式 → 检索/图谱注入 → 生成 → 引用审计 → 回答与来源渲染 → 全部落库。
3. **固定任务智能体**：选择任务类型 → 后端整理证据上下文 → 生成带编号草稿 → 自检失败则标注"需人工确认"。
4. **对照实验**：逐行输入题集 → 设置重复次数与固定种子 → 随机化"问题—模式—重复"顺序运行 → 后台队列与轮询 → 中断显式续跑 → 导出 CSV。
5. **盲评**：导出 CSV 方法隐藏 → 两名评价人打分 → 汇总一致性校验 → 完成门禁（`confirmatory_review_completion_gate.py`）。

### 7.2 测试与验证

| 测试类型 | 内容与结果 |
| --- | --- |
| 后端单元/集成测试 | Rust 测试覆盖认证、权限、RAG 检索、引用审计、嵌入、图谱、智能体、实验、盲评、安全边界；`cargo fmt/clippy/test` 全绿 |
| 前端检查 | `npm run lint`、`typecheck`、`build` 通过 |
| 系统级 E2E | 浏览器生产构建闭环、实验中途强杀恢复、短并发探针（`scripts/run-system-e2e.sh`） |
| 性能测试 | 90 请求/10 并发 p95≤2000ms、60 秒 soak 探针（`scripts/load_smoke.py`、`soak_smoke.py`） |
| 安全测试 | 生产配置检查、密钥卫生、密钥轮换手册预检、反向代理配置预检、npm audit（`scripts/check_*.py`） |
| AI 真实性验证 | 真实 DeepSeek 微型回归、RAG 证据复现（`result_sha256`）、检索指纹与配置比对（`scripts/evaluate_rust_retrieval.py`） |

| 成熟度门禁 | 内部门禁汇总检索指标、真实实验、智能体探针、运行态检查、备份恢复演练等；最终成熟门禁要求生产配置、外部冻结包、长时 soak、真实 TLS、异地备份证据（当前未满足项会显式 FAIL 并写入 blocker） |

## 8. 总结与展望

### 8.1 工作总结

已完成：核心业务闭环（笔记/资料/审核/权限）、五种模式 RAG 与图谱增强、固定与交互式智能体、MCP 开放服务、可复现对照实验与盲评体系、证据冻结与多级门禁、备份恢复与监控运维。

### 8.2 存在的不足

1. 交互式智能体（agent_runtime）与 MCP 是最新功能，尚未纳入成熟度门禁证据链；前端缺乏独立完整的智能体会话页面。
2. 论文效果证据仍依赖内部题集与内部编写规则，外部命题的确认性人工评审冻结包尚未完成。
3. 生产部署证据（真实 TLS、异地加密备份、长时 soak）缺失，最终成熟门禁当前为 FAIL。
4. 嵌入与生成强依赖外部服务（bge-m3、DeepSeek），未覆盖自托管/多供应商容灾路径。

### 8.3 展望

下一步工作包括：完成外部命题确认性评审与三方法（内部、外部、盲评）证据闭环；补齐生产部署与灾备证据；把 MCP/交互式智能体纳入门禁；引入更多真实科研数据集（多语种、多模态）扩展对照实验；探索自托管嵌入与生成模型以降低外部依赖。
