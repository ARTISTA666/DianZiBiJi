# 论文全文逻辑复盘记录（T-081，2026-09-24）

## 审查范围与结论

以 T-080《毕业论文-导师意见针对性精修副本-2026-09-24.docx》为只读基线，复核全文论证链、章节接口、关键数据口径和句级表述；所有论文修订只写入 T-081 独立副本。复盘涵盖摘要、第一至第七章和附录，回看了 T-079、T-080 记录中与当前逻辑相关的材料，并以第六章既有实验工件、审计表及运行记录限定事实范围。

全文的主论证链可以成立：围绕实验记录的项目权限、审核与来源追溯问题提出系统目标；第二章说明可用技术及其能力边界；第三章将场景转成需求；第四章给出设计与机制；第五章展示实现和案例；第六章分别核验功能、抽取、问答和机制；第七章按证据范围总结贡献并说明不足。主要问题不是缺少一章，而是个别关键接口把“设计/方案”写得像“效果/已验证机制”，或对照条件说得不够精确。

本轮发现并修订了几处会影响读者判断的逻辑点。最关键的是 RQ2：第一章原来容易让人理解为两组使用完全相同的证据、仅有无图结构不同；但实际实验是在共同 SOP 提要检索结果之外，给图谱增强组额外注入已审核笔记关系。现已统一写成“共同文档证据 + 额外关系证据”，并明确结果不能分离图结构与信息量各自的贡献。另将计划解析的无冲突留痕、修复后 F1=100% 与主实验受误抽关系影响等边界放回摘要、正文与结论；对未报告需求访谈/观察的内容改作设计范围说明，不再写成已证实的用户普遍痛点。

这轮复盘未找到需要改动实验原始值的证据。修订保留原始 4/20、14/20、52 条金标准关系、53 条原始关系、时延和 Token 等结果；新增的关系 ID、上下文题号和交叉引用用于交代证据及章节映射，不构成重算或新增实验结果。

## 章节接口复核结论

- **第一章 → 第二章 → 第三章：**研究动机转成 RQ，第二章给出方法选型背景，第三章将项目场景变为权限、审核、追溯等需求。需求来源的实证状态现已收窄说明；若将来补用户研究，应增加方法与样本，不能仅把“典型场景”改称实地需求。
- **第三章 → 第四章：**功能与非功能需求均能在设计章找到模块、数据状态或权限机制；屏幕适配等未测事项被标为设计约定，未伪称测试通过。
- **第四章 → 第五章：**架构、模块、流程和数据模型的观察角度不同，正文已说明不要求一一对应；第五章按实现链路组织，并有案例串接。
- **第五章 → 第六章：**样例与案例不充当效果证据；第六章另给测试记录、题集、指标、样本口径和结果。演示库样本规模、关系抽取专项样本、问答题集和历史模型运行之间有明确区分。
- **第六章 → 第七章：**RQ1 对应来源追溯走查/审计记录；RQ2 对应问答成对比较，但因组间信息不等量，只能得出关系证据增强方案的整体批次表现；RQ3 对应失败案例。功能检查、抽取核验、自动评分与回答事实性没有互相替代。
- **正文 → 附录：**问题清单、金标准核验与盲评协议可回到正文；盲评待签核状态明确。摘要、结论及局限没有把附录中的未完成材料写成已完成效果证据。
