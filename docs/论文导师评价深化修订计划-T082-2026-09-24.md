## 全篇逻辑审查路径

逐章按“本章要回答什么—依赖什么前提—给出什么材料—材料支持到哪里—怎样交给下一章”记录问题。全文主链逐环核对：研究背景与相关工作 → 可检验研究问题 → 需求及需求来源 → 设计机制 → 实际实现 → 数据和实验设计 → 结果 → 结论与局限。对每项结论反查分母、时间点、样本、系统版本、证据类型和外部适用范围；凡缺少实证或需新增实验的地方，只收窄结论并列为待办，不补造事实。

| 部分 | 重点细读与修订目标 |
| --- | --- |
| 摘要 | 逐句核对系统范围、原始抽取结果与修复后核对的区别、问答实验输入条件、负面结果和限制；确保摘要不比正文更强。 |
| 第一章 | 检查研究缺口是否由相关工作支持，RQ1–RQ3 是否边界清楚、可由后文回答；贡献与研究内容逐项对应，不把工程功能写成独立效果结论。 |
| 第二章 | 核对综述比较维度、引文支持与本研究选型之间的推理；区分既有研究能力和本文实现，检查重复引用及“综述结论→需求”的过渡。 |
| 第三章 | 每项需求检查其场景来源、角色/权限、可观测行为和后续验证；将设计场景与实地需求调查区分；统一角色、权限能力、计划机制和预警指标名称。 |
| 第四章 | 核对架构、能力矩阵、模块表、流程、数据库图、实体关系、抽取规则、RAG、工具确认、预警之间的映射；逐图表检查与相邻说明相符；区分设计承诺和已验证行为。 |
| 第五章 | 检查实现顺序是否服从实际数据流，代码/接口/截图/表格是否支撑文字；区分示例、历史快照、构造案例和效果证据；修复截图方位、术语、表格断词等问题。 |
| 第六章 | 按实验逐项重建问题—样本—数据来源—对照—指标—排除规则—结果—推论。优先重审 RQ2 两臂是否被误写成只改变图结构；将额外关系信息量、预先存在的噪声、答案后验制定和跨批次快照差异放到结果前可见的位置。检查分母、图表轴、题型题数、指标定义、单位、表内公式及正文/附录映射。 |
| 第七章 | 每条贡献与结论回链至明确结果；负面结果和局限与摘要及第六章一致；未来工作对应真实缺口，不把计划写成已完成。 |
| 附录与文献 | 核对题目例外、数据库字段/主键/唯一约束、工件路径与正文一致；检查文献 80 条、正文锚点、首次编号、相同题名条目和标点格式。 |

## 已发现的优先复核点

1. 第六章 6.3/6.6 的实验导语称两种模式“仅改变是否注入关系证据”，并有“相同资料证据”的简写；图谱组确实额外获得笔记关系信息。虽然 6.10 已说明不能分离图结构与信息量，但应把对照实际改变的因素、推论范围提前到实验设计和结果之前，并与摘要、1.3、6.10、7.3 一致。这是 P1 核心逻辑修订。
2. “计划知识点管理”“知识蓝图”已有术语说明，但首次解释位置、界面标签、指标名及各章简称仍须整体复核；不得把计划覆盖率写成实验任务完成率。
3. 第四章图 4-1 已从旧清单中的“33 张表”更新为“43 张表”，当前图内数字与数据库总数一致；本轮将其作为已解决回归项，不重画、不改数。
4. 当前 T-081 LibreOffice 渲染的 95 个目录项中有 13 个缓存页码与排版页不一致，T-080 基线也有相同差异。T-082 需要重新渲染并尝试同步目录字段/缓存；不得将继承自旧版的差异当成验收通过。
5. 100 页上限没有余量；新增解释应以替换、前置或合并重复信息为主。用户未提供的作者信息、签名、日期和致谢仍留空。
