# RAG 回答人工评价规则 v1

## 1. 评价人要求

- 使用独立评价账号，不与另一名评价人讨论具体答案。
- 评价前不查看模式解码键、原始问答日志或模式汇总。
- 只根据盲评页面显示的问题、回答和证据判断。
- 提交后评价不能修改，提交前应再检查一次。

## 2. 准确性

选择“准确”需要同时满足：

- 回答直接回应问题。
- 关键实体、编号、数值、条件和关系正确。
- 没有与证据冲突的重要附加信息。

出现以下任一情况时选择“不准确”：

- 样本、组别、登录号或数值映射错误。
- 关键事实遗漏，导致问题没有被完整回答。
- 将不确定内容当作确定事实。
- 在资料中无法确认时仍给出具体结论。

## 3. 可追溯性

选择“可追溯”需要同时满足：

- 每个关键结论均能在至少一条 `[E]` 证据中找到。
- 回答的证据编号指向与结论相关的内容。
- 证据能支持具体样本、数值或关系，不是只有一般背景说明。

只有部分结论有证据、证据编号不存在或证据与结论无关时，选择“不可追溯”。

## 4. 综合评分

| 分数 | 标准 |
| ---: | --- |
| 5 | 回答正确、完整、简洁，关键结论均有明确证据。 |
| 4 | 核心结论正确，只有不影响结论的小遗漏或表述问题。 |
| 3 | 部分正确，但有明显遗漏、多余内容或部分证据不足。 |
| 2 | 只有少量内容正确，核心映射、数值或结论存在错误。 |
| 1 | 没有回答问题、主要内容错误，或基本没有可用证据。 |

## 5. 备注要求

- 选择“不准确”时，备注中必须写明至少一个错误事实。
- 选择“不可追溯”时，备注中必须写明哪个结论缺少证据。
- 不在备注中猜测回答使用了哪种检索方法。

## 6. 汇总流程

1. 两名评价者分别完成同一批次全部回答。
2. 管理者检查每名评价者的完成数，未完成时不解盲。
3. 全部完成后统计准确率、可追溯率、平均评分、一致率和 Cohen’s kappa。
4. 分歧案例由第三人复核，但保留两名原评价者的记录。
5. 解盲后再按检索模式汇总，不删除不利案例。

系统管理员在两名评价者都完成后导出实验 CSV，再运行：

```bash
python scripts/summarize_system_reviews.py \
  --export docs/experiments/rag-experiment-5.csv \
  --expected-reviewers 2 \
  --output docs/experiments/rag-experiment-5-human-review-summary.json
```

脚本会检查每条回答是否有两位不同评价者、评价者集合是否一致、负面判断是否有说明、每个问题的方法是否齐全，以及每条评分是否由方法隐藏页面提交。混入 `unblinded` 管理复核记录或有一项不完整时，默认停止并且不生成正式汇总。

## 7. 证据边界

现有实验 4 的问题和规则由项目内部编写，其人工评价可用于测试评价流程，不能替代新的外部命题确认性实验。
