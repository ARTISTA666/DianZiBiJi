# RAG 公平对照协议 v1

## 材料与预先约束

本轮为内部、回顾性的工程对照。材料限于 T114 已冻结的公开 NCBI GEO GSE111619 派生记录、既有问题和文档检索快照；不声称新增独立留出集，也不代表本地实验室真实使用者。问题及参考答案保持不变，准备上下文时不读取参考事实进行证据筛选。论文、旧实验快照与旧冻结清单不改动。

脚本 `scripts/experiments/run_t148_rag_fair_compare.py` 将每份已批准记录的全部 fixed_fields 字段和完整正文映射为 `(来源登录号, 字段, 原值)`。数组元素各为一个原子值，不再按逗号拆分。每条事实保存笔记 ID、版本 ID、版本号和完整笔记快照 SHA-256。事实集合只是可复核的规范表达，不等同于独立人工金标准。

## 四个实验条件

| 条件 | 操作 | 可回答的问题 |
| --- | --- | --- |
| same_facts_text | 相同文档基底 + 全部规范事实的字段句表达 | 同一事实集合下的表达差异 |
| same_facts_triples | 相同文档基底 + 全部规范事实的三元组表达 | 与上一条件成对比较；输入长度允许不同 |
| budget_ordered | 相同文档基底 + 固定来源顺序的三元组，逐条填入预算 | 相同预算上限下的证据装载基线 |
| budget_query_ranked | 相同文档基底 + 按问题词项重合排序的三元组，逐条填入预算 | 与上一条件成对比较；不使用参考答案排序 |

文档基底先统一截取，之后四条件保持完全一致。预算条件只保留整条事实，并复核完整 system/user 消息内容的估算 token 数不超过 1536；文档内容统一上限为 400。两条件使用相同上限，实际消耗和保留事实数量可以不同。本协议不把“同一上限”写成“相同实际 token 消耗”。

计数采用官方 [DeepSeek V4 tokenizer](https://github.com/deepseek-ai/deepseek-recipe/blob/main/static/tokenizers/v4/README.md)，本地文件 SHA-256 为 `97d2f31b020d18b5aee5c9b3d5b4efb10ea210f3fe3f7dffe3f1cd90542d6b19`。计数范围仅为消息内容，未模拟服务商 chat framing；属于离线估算，服务端 `usage.prompt_tokens` 单独保留，作为实际请求的计数依据。官方也说明离线估算与实际处理可能有差异：[Token & Token Usage](https://api-docs.deepseek.com/quick_start/token_usage/)。

## 生成与冻结

12 个既有问题 × 4 条件 × 1 次生成，共 48 个计划请求。固定随机种子 `20261012148` 预先打乱提交顺序，并发最多 3。统一使用 DeepSeek API `deepseek-v4-flash`，temperature=0.1，max_tokens=1000，thinking=disabled；单请求 timeout=180 秒、最多 2 次尝试，仅对传输错误及 429/500/502/503/504 重试。请求、参考、规范事实、各条件上下文、协议、脚本、tokenizer、模型参数与顺序均先写入新的冻结清单，生成前后复核哈希。仅上传公开科学材料与问题，不上传论文、用户私有笔记或凭证。

保留成功和失败请求、原始服务商响应、实际模型名、响应 ID、finish_reason、usage 和耗时。失败不以 reasoning 字段代替答案，输出截断视为失败。结果文件独占创建，拒绝覆盖；本版本不自动续跑部分批次，也不剔除失败重新挑选结果。

## 分析和证据边界

辅助指标为既有参考别名的词面覆盖率。分析单位为问题，成对差异仅使用两条件均完成的题目，报告计划数、实际成功数、失败与缺失；bootstrap 10000 次，精确双侧 sign-flip，全部推断均为探索性。唯一预定主对照为同事实集合三元组减文本表达；预算选择对照为次级工程比较。重复生成不得增加独立问题样本数。

词面覆盖不能证明语义蕴含、样本与数值绑定、引用忠实度。此批次不执行独立人评，也不据此声称图拓扑的独立因果收益。单次生成不能证明随机波动稳定性；真实中文记录与多来源外推仍待独立材料验证。结果先单独保存，暂不同步论文。

## 验收

1. 相同事实条件的 fact ID、原值和来源快照集合逐题完全一致。
2. 四条件的文档基底逐题一致，预算条件完整消息内容估算值均不超上限。
3. 运行前后冻结哈希通过；计划与结果 ID、提示哈希一一核对，失败与缺失完整披露。
4. 工程测试与新结果分别登记，不回改任何历史运行结果。
