## 1. 旧40条回答交叉评判

归档实验4的20道题、两个方法共40条回答为输入，保留当时真实检索上下文及事后参考事实，不补写更有利的参考。统一将来源编号映射为E编号；题序按固定种子随机化，评判包不含方法名、前次分数与组别统计。图关系形式仍可能暴露来源结构，记录残留方法可辨性。

GPT来源为独立Codex子代理，未将当前会话虚记为官方GPT API；每组使用fresh context，输入仅匿名评判包、统一提示和schema。原计划DeepSeek补评因作者随后选择“均保留本地”而取消执行。已冻结的计划记录保留未执行状态；本轮由GPT对旧DeepSeek生成回答使用claim-support-v1逐主张支持、参考事实覆盖、上下文相关性、有效引用评分定义。这是本轮自定义结构化评分，不冒称RAGAS分数或真人盲评。

冻结40条匿名输入、映射、提示、schema、随机种子、模型来源与采样参数后执行。保留每条原始响应、引用证据位置、评分理由、有效样本和失败；GPT结构不合schema允许一次纯格式修复，实质性原判不更改；失败为缺失不置0。评判结果按sample_id及input_sha256绑定，拒绝缺漏/重复/错配输入。按问题配对计算两个检索方法间差值与区间，报告GPT有效题数。历史DeepSeek RAGAS采用不同指标，不能与本轮自定义分数相减或计算同标一致性。旧题规则形成于生成后，新增评判不能消除该历史偏差。

## 2. 当前Rust前置规则复测

### 问题与语料

依据公开GSE111619源记录重新制定12道问题，逐题冻结required facts、别名、禁止错误事实或拒答条件、源文件与定位。AI制题者不读取该批生成输出，规则一旦冻结不得按回答调整。本轮没有独立人类题集制定者，且不声称与全部历史问题语义去重后的holdout。

在独立eln-t114 Compose项目、独立PostgreSQL/storage卷及127.0.0.1:18014运行生产Rust后端，导入4份来源派生文档与4份笔记；删除公开原始metadata中的contact行，以最小化无关个人元数据。原始count矩阵保留本地并记录哈希，上传其来源已核验摘要，不外发整矩阵。导入、提交、审批、抽取与索引均发生在第一条生成前；冻结批准笔记、活动图关系、检索快照、文档chunk、模型和模板配置。

### 四臂

- A 文档检索：当前Rust project_rag实际返回文档片段。
- B 文档＋全文笔记：同一A片段，补充全部批准笔记的正文及结构化字段。
- C 文档＋全部三元组：同一A片段，补充当前图全部活动三元组及来源笔记标识。
- D 文档＋一跳关系：同一A片段，补充当前Rust kg_enhanced_rag实际返回的一跳graph_context。

全文笔记与全部三元组是冻结上下文适配器，不伪称生产接口原生模式。四臂同一生成模型deepseek-v4-flash、temperature=0.1、max_tokens=1000、同一system/user模板，最多两次尝试。作者2026-10-01随后澄清“项目需要deepseek继续回答的还是需要调用该接口”，授权项目回答继续使用原接口；GPT交叉评判与角色决策保留会话内。每题3次重复，以固定种子随机化144个请求；共享文档base上限4000字符、补充上限16000字符，whole block截断规则提前固定。若完整笔记/三元组不能装入补充预算，生成前终止准备、报告缺口；不在看到输出后加大预算。各臂真实上下文字符及实际API token用量单独报告，不能把信息量差异写成纯图结构因果效应。

冻结前准备中，初设12000字符不足以容纳实际100条关系（13064字符），在未发生任何新生成调用时将共同补充上限确定为16000字符。保留此准备失败，全部关系不删减；最终冻结以后不得按答案改预算。

### 评分与分析

主指标由独立GPT对子答案逐个必需事实做语义评判，核查事实是否表述、样本与字段绑定是否正确、是否由实际提供证据支持；引用连续原文、实际E编号和判读理由。主比较D与A，次要比较D与B、D与C。关键词别名匹配仅作辅助，不替代语义评判。两道纯资料不足题单列拒答正确性，不与10道含事实题的覆盖率混算。另报告禁止正向断言、严格任务成功、引用、延迟和token。标识有效不等于内容支持。缺失不记为0，报告每题/臂有效重复数与完整配对题数。

同题3次重复先汇总，再以题为单位计算成对差值、95%bootstrap区间（固定seed、10000次重采样）；不得把36重复当36独立题。次要两个比较如使用显著性检验须Holm校正；样本量小，区间和效应优先，不据此推断跨实验室普适收益。新批次只说明当前Rust、当前公开派生语料下的前置规则复测，不能替换2026-06-11历史结果。

## 3. GPT多角色模拟验证

使用另一个独立模拟项目，避免修改第2部分冻结语料；四个GPT角色为学生/记录者、导师或项目审批者、只读成员、无成员权限账号；管理员由执行脚本观察核验。八类固定任务各三次，共24个场景：创建并提审、退回、修改并再提审、审批、事实问答、资料不足问答、只读写入拒绝、非成员读取拒绝。具体判定和修订记录先冻结于simulation/protocol-v2.json（源CSV核对纠正初稿手录的GSM编号，发生在任何角色动作之前）。super_admin有合法全局访问权，不将该角色的授权读取误记为越权。

模型角色问答实际调用Rust rag/query，由配置的DeepSeek生成；GPT模拟角色根据结果选择后续动作。每个模型角色取得固定任务和允许权限，但不预先提供执行动作或结果。依据实时API响应选择后续动作，保存输入、动作、状态码、关键响应摘要、开始/结束时间及原始GPT说明。任务成功条件先冻结；若只进行场景文字判断，则另列为情境模拟，不能冒称实际使用流程。模拟结果只支持工作流可执行性和暴露问题，不用于估计真人满意度、操作负担、采用率或访谈主题。
