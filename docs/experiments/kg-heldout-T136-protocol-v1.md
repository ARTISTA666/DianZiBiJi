# T136 新来源实验笔记关系抽取协议 v1

2026-10-10 作者授权执行一轮新测试。问题：原四条固定样例的高分，能否在新的公开实验日记上重现；结构化字段映射与自由正文抽取的表现是否不同？本轮不修改生产抽取规则，不改论文数字，不覆盖历史结果。

## 输入与选择

新取得三份公开 iGEM 实验笔记 PDF（IISc Bangalore 2019、British Columbia 2021、teams/5863 notebook，第三份封面身份在来源清单核实）。每份按原文阅读顺序选最先四个自含、已执行的实验日记单元：正文 60–2500 字符，明确至少两个试剂、仪器、样本或观测结果事实。跳过封面、纯表格/图像、纯计划、仅引用外部 protocol 的条目，保存跳过原因。允许合并连续的同日段落；不得按系统效果挑选。原文仅整理 PDF 硬换行/连字，不翻译、不补造事实。目标 12 条，不足如实报告。

首次下载及本地未使用检查只能支持“本仓库本轮新取得的测试输入”，不能证明预训练模型从未见过公开文档。输入是英文，不能据此估计中文自然笔记的总体表现。元数据标题及实验类型由选材 Agent 赋值，与原文科学事实分开。

每条自然笔记运行两个配对输入：

- `body`：只提供英文原文，`fixed_fields_json={}`，测自然正文关系抽取。
- `fields`：将输出前参考标注的客体标签映射为结构化字段数组，正文为空。这是给定正确字段的映射对照，不计入自动理解原文的成绩。

原四条固定样例另设 `regression`，保留当前 Rust 种子输入，沿用旧 52 关系参考；仅检查历史样例在当前 Rust 的表现，不混入新语料分母。

## 输出前标注和冻结

research-reviewer Agent 仅依据输入及以下 schema 标注；product-manager Agent 在未查看新系统输出前复核证据、分类及遗漏；root 裁决分歧并记录理由。本轮没有真人标注者，参考集合称为 **AI 辅助参考标注**，不可称人工独立金标准。

标注单位是已执行记录中明确的 `(笔记, 关系类型, 客体类型, 客体标签)`，每项保留原文证据片段。关系类型为 `uses_reagent/reagent`、`uses_instrument/instrument`、`uses_sample/sample`、`produces_result/result`。只标显式事实，不把未来计划、文献转述、预期目标变为观测结果。试剂包括使用的培养基/缓冲液；仪器是明确提及的设备；样本是实验处理的生物或材料对象；结果保留完整观测语句，不推断数量。相同事实去重。原文存在不能稳定分类的项目须输出前列为排除项及理由，不依输出增删。

输出前语义裁决：仅写“prepared/autoclaved”的最终缓冲液/培养基成品不强行标为 `uses_reagent`，制备/灭菌动作自身不作为观测结果；明确列出的配制成分可标为组成输入，不补未出现的原料/仪器。选择条件的两个显式事实不等于必有两个可稳定归入目标 schema 的关系。目标参考为空的记录保留为 schema 外/负例，按上面的空集合规则计分，并报告有参考关系的笔记数量；不因关系少更换记录。裁决与双方复核一并冻结。

原文、标注、裁决、结构化对照、旧样例参考、评分脚本和本协议在首次笔记 API 导入前计算 SHA-256，写入冻结清单并校验；完成全部输入后才执行。之后不得调整主分析参考以匹配输出。任何工具错误及重跑必须保留失败记录；代码规则保持不变。

## 计分

每条笔记按完整主体及类型匹配，`has_note` 的主体是本次项目，其余主体是该笔记。匹配键包含逻辑笔记 ID、主体类型/标签/稳定身份、关系类型、客体类型/标签/稳定身份；仅做 Unicode NFKC、首尾/连续空白统一及大小写折叠，不做模糊、子串、数字补全或别名匹配。关系按完整键去重，另报原始行数、重复数据库关系 ID 数及重复评分键数；完全匹配指关系集合相等，重复状态另报。不得用标题相同而主体错误的关系算 TP。

元数据独立计分：`project --has_note--> note`、`note --created_by--> user`、`note --has_experiment_type--> experiment_type`，每笔记期望 3 条。业务内容四类独立于元数据，分别报告 TP、FP、FN、micro P/R/F1、逐笔记结果、macro F1 和完全匹配笔记数。`all` 只指上述七类评分关系；其他关系另报数量和类型。P=TP/(TP+FP)，无预测时 P=null；R=TP/(TP+FN)，无参考时 R=null；F1=2TP/(2TP+FP+FN)，两集合皆空时 F1=null，完全匹配为真。macro F1 只取非空分母笔记并给出数量。

两臂是同一 12 条笔记的配对变体，不能视为 24 个独立来源；同一笔记内多条关系也不作为独立样本。本轮是小规模机制检验，不做总体无误率、显著性或人工实际使用效果推断。

## 执行与复核

新 Compose project `eln-t136`，全新数据库/storage 卷，`SEED_DEMO_DATA=false`，API `127.0.0.1:18036`。复用镜像 `sha256:f39264ceca846f14d87559e972206fdfd0ba0c10731aadf90b8b3c8a2995552e`，`/ready` revision 必须等于 `b6cd3a24f6edb5bdf971d8d76cc7635139b32954`，并确认当前 Rust 构建输入相对该 HEAD 无差异。禁止调用外部生成或嵌入模型；此机制为 Rust 本地规则抽取。

API 链为登录、创建独立项目、创建 draft 笔记、submit、approve、获取单笔记 graph。测试管理员完成作者/审批两步，属于功能测试，不代表真人业务审批。保存请求（认证秘密删去）、状态、笔记/项目 ID、图谱完整响应、规范化关系、逐条错误、环境和版本。首次完成后对每条已批准笔记调用 `kg/extract(rebuild=true)` 一次，比较内容关系集合稳定性；重复结果不作为独立样本或扩大分母。

scorer 对错主体、错类型、重复、漏抽/误抽、零预测及冻结漂移做单元核验，并运行仓库要求的脚本测试。architect Agent 在冻结后审计脚本/原始输出与汇总算术。输出报告和可复算 JSON/CSV，作者验收状态单独登记。
