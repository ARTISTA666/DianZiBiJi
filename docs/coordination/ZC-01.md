### 3.1 实验 A（蓝图有/无 → 建议质量）

- **主张（原报告口径）**："蓝图使建议从通用提醒变为可执行、可核验、零编造的导引"。
- **实现**：rule_based 建议算法（系统真实兜底路径）作用于真实蓝图 15 节点；通用静态建议为对照臂。
- **证据**：可执行引用 3 vs 0；命中待实证 3 vs 0；编造 0 vs 0。
- **Codex 指出的缺口（采纳）**：3 比 0 仅是**兜底建议与静态提醒的引用绑定对照**——它证明的是"蓝图输入使建议携带项目具体引用"，**不足以证明"建议质量/可执行性"整体**：(a) 对照臂（静态提醒）是弱基线，未对比"无蓝图但有项目笔记摘要"这类更强基线；(b) rule_based 是模板拼接，未经 LLM 归纳臂与人类评判；(c) "可执行"仅指引用真实存在，未验证按建议执行的成功率。
- **修正口径**（ZC-02 再修正 2026-09-07 21:52）：本证据支持的主张收窄为——**"蓝图输入下兜底建议的 3 条引用全部绑定真实待实证知识点且无编造；通用静态提醒臂为 0 条引用"**。这是**引用绑定计数对照**，不构成比率型质量指标（"0/0"分母为零的比率无意义，不作"0% 编造率"类表述），不主张建议的整体质量、可执行成功率或 LLM 臂优势。

- **修正口径**（ZC-02 再修正 2026-09-07 21:52）：实验 B 的定位收窄为——**"设计文档（原型级）的重打分机制在离线脚本中可复现并具方向性判别力；生产系统当前不包含画像重排，故不存在任何真实收益主张"**。且按 Codex ZC-02 指定：**学生画像属于核心三贡献之外的前瞻项（outlook）**，论文中不占用贡献条目，仅可作为展望或附录原型材料。创新点五在论文中的证据级别 = 设计文档 + 离线原型验证。

### 3.3 实验 C（语义映射有/无 → 识读）

- **主张（原报告口径）**："全通道映射把 O(N) 遍历压缩为 O(1) 通道读取"（机器代理）。
- **实现**：三类识读任务 × 两视图的通道数成本模型；节点类型分布保证答案非空。
- **证据**：86 步 vs 1 步（成本模型推算）。
- **Codex 指出的缺口（采纳）**：86 比 1 是**人为成本模型**——操作步数是建模假设（假设逐节点点开 = 1 步/节点、通道可读 = 1 步），**不能当作实际 86 倍效率，更不能当作人类识读的 O(1) 证据**；视觉通道"单步可读"本身也是待验证假设（颜色可并行感知，但水波高度与大小通道可能需要注视切换）。
- **修正口径**（ZC-02 再修正 2026-09-07 21:52）：实验 C 仅支持——**"语义映射为三类识读任务各提供一条专用视觉通道（机制完备性，通道-任务绑定可从映射表逐条核对）"**。86:1 既非实测效率，也**不构成任何实测下界**——它是建模假设的推演值，两处假设（逐节点 = 1 步、通道可读 = 1 步）均未经验证。禁止在论文或汇报中以任何倍数形式引用。另据 AG-01/AG-02：形状与水波通道已在当前 HEAD 裁撤（收敛为纯圆+抽屉读数），消融实验 C 的"水波通道 1 步"论据对应的是 4606189 演示版本而非当前实现，通道表述以 AG-02 后的映射文档 v1.1 为准。
- **最小补证方案**：人工两条件被试实验（有/无语义映射截图，找类型/找枢纽/判断时效三类任务，计反应时与正确率，课题组内 3-5 人）——与用户测试批次合并执行，预计半天。在此之前，论文对该创新只写机制设计 + 图例，不写效率数字。
