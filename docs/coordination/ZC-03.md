## 贡献 ① 动态图谱建模更新

### ①-A 蓝图解析的增量更新代价（对应 DS-01 S3 LightRAG 差距）

| 要素 | 设计 |
| --- | --- |
| 研究问题 | 蓝图增量解析（新增/覆盖/保持三态合并）相比全量重建，耗时与受影响规模是否可控 |
| 公平对照 | 同一计划文本两条件：**A1 首次解析**（空蓝图）vs **A2 二次解析**（已有 15 节点蓝图后重解析）；如需更强对照，A3 = 清空后全量重建（需管理权限作废节点，属破坏性操作，标注为可选） |
| 数据来源 | 运行库项目 10 真实计划文本 + `kg_blueprint_documents` 解析留痕（节点/边增删计数、消息字段）+ 后端请求日志 duration_ms；解析动作经页面或 API 触发 |
| 指标定义 | ①每次解析墙钟时间（ms，取后端日志）；②受影响节点比例 = (nodes_added+nodes_updated+edges_dropped)/total_nodes；③幂等性 = 二次解析 added=0 且内容不变 |
| 失败判据 | 二次解析仍产生大量新增（幂等失败），或耗时随蓝图规模线性爆炸且无法归因（日志缺失）→ 如实报告"增量优势未证实" |
| 资源成本 | 低：2 次 API 调用 + 日志提取，约 15 分钟；**需运行栈**（部署标签 4606189，镜像内容未核实——结果仅归因到"运行中系统"，不归因到具体 commit） |
| 论文章节 | 5.x（蓝图机制）/ 7.x（系统实验）：增量更新代价小节 |

### ①-B 蓝图输入对建议引用绑定的增益（ZC-01 实验 A 的规范化重述）

| 要素 | 设计 |
| --- | --- |
| 研究问题 | 蓝图未覆盖知识点清单作为输入，是否使建议引用绑定率高于无蓝图输入（**只主张引用绑定与覆盖指引，不主张正确性**） |
| 公平对照 | **三臂分离，规则与 LLM 不混合**：B1 = 兜底算法 + 蓝图输入（已有数据）；B2 = 兜底算法 + 通用提醒（已有数据）；B3 = LLM 归纳 + 笔记列表输入（无蓝图强基线，**需调 LLM，属新实验，本轮不运行**）；B4 = LLM 归纳 + 蓝图输入（线上端点已有，取审计日志即可补录）。对照公平性关键：同输入长度、同 prompt 版本、同 temperature |
| 数据来源 | B1/B2：`docs/experiments/innovation-ablation-2026-09-07.json`（已有）；B4：audit_logs `agent_next_step_suggestion`（mode=llm 记录）；B3：未采集 |
| 指标定义 | ①引用绑定数（建议中 related_labels 命中项目真实知识点的条数）；②命中未覆盖知识点数；③编造引用数；④覆盖指引数（建议∪集合对待实证清单的覆盖率）。**明确不定义"建议正确率"**——无人工标注前不可测 |
| 失败判据 | B3/B4 编造引用 > 0 且防编造校验未拦截 → 如实报告校验缺口；蓝图臂与强基线臂引用绑定无差异 → 蓝图增益主张撤回 |
| 资源成本 | B1/B2/B4 零新采集（整理已有数据约 30 分钟）；B3 需 1 次 LLM 调用授权（约 5 分钟 + API 费用可忽略），**排在人工评审批次一起** |
| 论文章节 | 5.x（建议生成协议）/ 7.x：蓝图输入增益小节（只写引用绑定与覆盖指引两指标） |

## 贡献 ② 图谱与证据约束的科研辅助工作流（含预警）

### ②-C 建议的行为证据：采纳/忽略留痕（对应 DS-01 M3）

| 要素 | 设计 |
| --- | --- |
| 研究问题 | 主动建议是否被学生真实使用（行为分布），能否形成工作流闭环的行为证据 |
| 公平对照 | 前后对照：**C1 上线采纳留痕前**（audit_logs 只能事后追溯：建议引用的知识点 vs 其后 approve_note 抽取的实体是否命中）vs **C2 上线采纳留痕后**（显式采纳/忽略/过期三态计数）。C1 为追溯代理指标，C2 为直接行为指标，两者分别报告、不混算 |
| 数据来源 | C1：audit_logs（`agent_next_step_suggestion` + 其后 30 天 `approve_note` 的 KG 实体，SQL 关联）；C2：需新增一列状态与两按钮（**属源码改动，本轮只设计不实现**，列入待授权开发项） |
| 指标定义 | C1：事后追溯命中率 = 建议引用的知识点中在其后被该学生实证覆盖的比例（**注意：此为相关不是因果**——学生可能本来就要做）；C2：采纳率、采纳响应时长、忽略率 |
| 失败判据 | C1 命中率与"随机知识点基线"无差异（需定义基线：同类型未覆盖知识点的自然覆盖速率）→ 报告"无行为证据" |
| 资源成本 | C1 低：纯 SQL 离线分析，约 1 小时，**当前演示数据 9 条笔记可能不足以得出稳定结论，样本量如实标注**；C2 中：一次前端+后端小改动，需单独授权 |
| 论文章节 | 5.x（工作流）/ 7.x：建议行为证据小节 |

### ②-D 预警闭环的功能与效果分离验证

| 要素 | 设计 |
| --- | --- |
| 研究问题 | 分两层：D1（功能层）四维指标计算是否正确、报警生命周期是否完整（已有集成测试覆盖）；D2（效果层）预警是否改变审核停滞（**当前无任何证据，功能存在不能证明效果**） |
| 公平对照 | D1：指标值 SQL 手工重算 vs 系统评估输出一致性（无新实验）；D2：**同一实验室前后两周期对照**（关预警周期 vs 开预警周期，或组间对照）——属用户试用批次，本轮只定协议 |
| 数据来源 | D1：`project_alerts`、`project_alert_thresholds`、SQL 直查；D2：试用周期内 `experiment_notes`(SUBMITTED).updated_at 与 approve 时间差、`alert_acknowledge` 响应时长（审计日志） |
| 指标定义 | D1：指标重算一致率（4 指标 × N 次评估）；D2：①平均审批停滞时长变化；②critical 报警到确认的响应时长；③报警确认后指标的回落比例。**前提条件：需要真实多用户试用，当前数据不可测（未核实有足够样本）** |
| 失败判据 | D2 两周期停滞时长无显著差异或试用样本 < 预注册最小样本 → 效果主张不写入论文，只写机制与功能验证 |
| 资源成本 | D1 低：离线 SQL 核算 30 分钟；D2 高：依赖课题组试用排期（人工介入项），协议先行 |
| 论文章节 | 5.x（预警机制）/ 7.x：功能验证小节（D1 可写）+ 8.x 展望（D2 协议） |

## 贡献 ③ 导师监督的语义可视化反馈

### ③-E 语义映射的通道完备性与人类识读（AG 协同，ZCode 只定协议）

| 要素 | 设计 |
| --- | --- |
| 研究问题 | E1（机制层）：通道-任务绑定是否完备（每个识读任务有专属通道）；E2（效果层）：语义映射是否缩短识读时间、提高正确率（**当前零证据；86:1 为成本模型推演，不得引用**） |
| 公平对照 | E1：映射表逐条核对（已有，AG-01/AG-02 负责文档现状）；E2：**被试内两条件**——同一组导师/学生分别用"全语义映射截图"与"单色默认视图截图"完成三类任务（找类型/找枢纽/判断时效），条件顺序随机化抵消学习效应；刺激物为静态截图（**版本注明"工作区当前版本，具体构建未核实"**），不要求可交互 |
| 数据来源 | E2：人工测试记录表（反应时、正确率、任务序号、被试编号）；截图 2 组 × 3 任务；被试 = 课题组内 3-5 人（**样本量小，只作探索性结果，论文明示边界**） |
| 指标定义 | E2：每任务反应时（秒，从展示到口头回答）、正确率（答案与图谱真实数据比对，真实数据由 SQL 直查固化）、SUS 或单题 5 分制易读性评分（可选） |
| 失败判据 | 两条件反应时/正确率无差异或方向相反 → 如实报告；被试 < 3 → 只作个案描述不入统计 |
| 资源成本 | 中：准备截图与记录表 1 小时 + 测试执行 1 小时；**归属：AG 第三轮负责贡献三论文素材与自身文档残留修正，测试执行建议与用户测试批次合并排期** |
| 论文章节 | 5.x（可视化设计）/ 7.x：识读实验小节（探索性，样本量明示）或 8.x 展望（若未执行） |
