## 1. 用户目标与工作原则

用户要求继续项目优化迭代，但必须严格以论文撰写和可信证据为导向。后续工作优先级为：

1. 可复现的实验设计；
2. 数据集、问题集和实验案例绑定；
3. 评价指标、统计分析和失败案例；
4. 版本、参数、模型、提示词和语料快照记录；
5. 引用审计、证据链和可直接引用的论文材料；
6. 每一阶段运行与改动对应的验证。

不得把界面润色、炫技型 AI 功能或自动门禁分数当作论文贡献。没有人工金标准、独立盲评或确认性证据包时，必须明确写成“尚未具备论文确认性结论”，不能补造结果或把内部开发数据升级为正式结论。

## 4. 0–113 轮推进的主题概览

完整逐轮任务、原因、改动、测试、论文价值和 gatekeeper 结论见 `NIGHT_LOG.md`。以下是迁移时需要掌握的主线：

### 4.1 基线和系统边界

- 建立 `NIGHT_CONTEXT.md`、`NIGHT_BACKLOG.md`、`NIGHT_LOG.md`。
- 确认 Rust/Axum 是生产运行时，历史 Python 不能被误当作生产后端。
- 对本地 health/ready、OpenAPI、数据库/存储和真实浏览器路径做过基线验证。
- 登录、项目、笔记、资料、AI 问答和知识图谱页面的基本导航已验证。
- 发现并记录 `localhost` 与 `127.0.0.1` 混用可能导致 HttpOnly cookie 会话恢复失败；只增加诊断，不擅改认证边界。

### 4.2 证据包、执行计划和失败分母

- 证据包包含题集、方法、重复次数、随机化顺序、执行计划和执行计划哈希。
- 检查器重建执行计划并重新计算 SHA-256，拒绝计划漂移。
- `queued`/`running` 等非终态不能作为论文归档；`completed`、`completed_with_errors`、`interrupted` 和 `failed` 有不同的失败/未执行语义。
- 运行级故障和案例级故障通过 `failure_scope`/`failure_code` 机器可读区分。
- `total_cases = completed_cases + failed_cases + unexecuted_cases`，不允许删除异常案例或把运行级失败改写成成功。
- 未落库失败仍保留为 `status=failed`，`query_log_id=null`，并保留错误和失败分母。

### 4.3 题集、方法和逐案例身份

- 五种方法固定为：
  - `pure_llm`
  - `bm25_rag`
  - `project_rag`
  - `structured_query`
  - `kg_enhanced_rag`
- 题集要求非空、最多 50 题、题目唯一、单题长度 1–4000 字符。
- 方法数组要求非空、最多 5 个、唯一且只允许上述五种方法。
- 全量 CSV 行逐字绑定冻结题集索引、题目 ID 和题干，失败案例还会独立重算题干绑定。
- `question_index`、`repetition_index`、`execution_order` 从 1 起始。
- `experiment.name` 非空且最多 255 字符。

### 4.4 引用审计和失败案例

- 严格接受 `[S1]`、`[S2]` 和 `[G1]` 等单项引用标记；范围形式、非数字、越界引用失败关闭。
- 独立重算答案引用数量、非法引用、证据类别覆盖和关键事实段落引用规则。
- `citation_audit` 不能只被信任；报告值必须和独立重算值完全一致。
- 失败案例由原始 CSV、题集、审计 JSON 和论文材料逐层约束。
- 当前内部批次中曾稳定重算出 4 条严格引用失败案例，并保留 CSV 行、题目、方法、重复编号、`query_log_id` 和证据计数；这些是格式/审计失败证据，不应解释成事实错误或因果机制。

### 4.5 参数、版本和 retrieval snapshot

- 逐案例运行标签绑定 `provider`、`model`、`prompt_version`。
- 新 Rust CSV 导出原生追加逐案例 `retrieval_config_json` 及稳定字段，包括语料快照、索引版本、嵌入模型、检索策略、top-k、候选数、chunk、图谱 top-k 和阈值等。
- `graph_schema_version` 固定记录并在执行开始、恢复和每个案例前检查漂移。
- 历史实验 5 的 CSV 缺少大量逐案例 retrieval snapshot；本轮修复生产导出能力不会追溯修复历史数据，所以历史批次仍必须保持 `paper_ready=false`。

### 4.6 论文门禁与材料可追溯性

- `paper_ready`、`paper_blockers` 和详细 `checks` 的推导必须一致。
- 固定门禁集合有覆盖审计，正文中的失败摘要必须能够回到 JSON 的实际值/期望值。
- 描述性材料不生成准确率、引用正确性、显著性或方法优越性结论。
- 材料中的输入路径使用仓库相对 POSIX 路径，指纹为完整小写 SHA-256。
- freshness 检查会重新计算输入材料，防止论文 Markdown 与脚本、协议、审计 JSON 漂移。

### 4.7 API/OpenAPI/前端契约同步（103–113）

最近 11 轮重点把生产 Rust、离线检查器、OpenAPI 和前端生成类型对齐：

- 证据端点对盲评访问返回 `403`，对 queued/running/未知状态返回 `409`。
- OpenAPI 明确引用 `RagEvidencePackage` 和 `ApiErrorResponse`。
- `RagEvidenceExperiment` 的状态、方法、题集、重复次数、执行计划哈希和名称约束进入 OpenAPI。
- `RagEvidenceCase` 的 required 字段、方法枚举、身份字段、失败元数据和证据对象约束进入 OpenAPI。
- 第 113 轮新增：`query_log_id` 必须是正整数或 `null`；`response_ms` 必须是非负整数。
- Rust OpenAPI contract test、前端生成类型和实验协议均同步。

## 9. 当前可以写入论文的内容与不能写入的内容

### 可以写入

- 系统采用 Rust/Axum、Next.js、PostgreSQL/pgvector 的实现边界。
- 实验协议如何绑定题集、方法、重复、执行计划和输入版本。
- 如何保留逐案例证据、引用审计、失败分母和运行遥测。
- 证据包如何进行 fail-closed 审计、重算、渲染和 freshness 复核。
- 当前内部批次存在的 retrieval snapshot、外部冻结输入和人工评审缺口。
- 具体失败案例作为“证据链/引用格式失败案例”，不扩展为事实错误。

### 不能写入为确认性结论

- 某方法优于其他方法。
- 自动引用审计等于引用内容正确。
- 来源数、图谱命中数等于检索相关性或答案正确率。
- 自动 Agent quality 分数等于独立人工评价。
- 当前内部开发批次等于确认性实验。
- `paper_ready=false` 的材料可以作为正式效果结论。
