# 面向科研实验记录的智能电子实验笔记系统设计与实现

## 摘要

科研实验记录是实验过程复现、数据追溯和成果产出的基础材料。在高校科研课题组中,实验人员每天产生大量实验记录,包括实验条件、操作步骤、试剂耗材、仪器参数、样本信息和观察结果等。这些记录既是科研人员复现实验过程的依据,也是团队协作、项目交接、成果发表和数据审查的重要材料。传统纸质实验笔记和普通电子文档虽然能够保存实验过程的基本信息,但在项目协作效率、附件资料统一归档、实验知识之间的关联组织、项目级别的数据权限隔离以及 AI 辅助问答的来源追溯方面仍存在明显不足。特别是在多成员、多项目的课题组管理场景中,实验记录既需要经过审核流程确认后才能沉淀为可信知识,又需要在 AI 问答过程中保持严格的项目边界和可核查的依据来源。因此,本文关注的核心问题是:如何在项目级权限约束下,将经过审核的实验记录转化为可追溯的结构化知识,并在此基础上构建可评价的智能问答系统,使科研人员能够安全、高效地利用 AI 辅助能力进行实验数据查询和分析。

围绕上述问题,本文设计并实现了一套面向科研实验记录的智能电子实验笔记系统。系统以项目为基本管理单元,支持用户管理、课题组管理、项目成员与角色分配、实验笔记全生命周期管理、实验模板定制、附件资料上传审核、审批流程和审计日志追溯等基础功能。在知识组织方面,本文构建了面向实验记录的项目级知识图谱模型,将项目、实验笔记、实验人员、附件资料、实验类型、试剂、仪器、样本和实验结果等九类对象抽象为实体类型,将"包含笔记""创建者""关联附件""实验类型""使用试剂""使用仪器""使用样本"和"产生结果"等八类实验语义抽象为关系。知识图谱的抽取时机与实验笔记的审核状态绑定,仅在笔记审核通过后自动触发抽取,草稿和未审核内容不会进入知识图谱。

在智能问答方面,本文设计了融合实验知识图谱的项目级检索增强生成流程。系统将审核通过的资料同步至项目知识库作为问答基础,在用户提问时根据问题内容检索项目内的相关图谱关系,并将结构化的图谱上下文与资料检索结果共同作为回答生成的依据。系统支持普通项目 RAG 和图谱增强 RAG 两种模式的切换,每次问答记录保存模式标识、图谱命中数量、资料来源数量、响应耗时、来源依据详情和人工评价结果,为普通 RAG 与图谱增强 RAG 的效果比较提供数据基础。对于实验总结、周报、阶段报告和图谱概览等周期性或阶段性文书整理任务,系统采用固定任务型智能辅助生成方式,根据预设的任务模板从数据库检索已审核实验笔记、资料和图谱关系生成结构化的总结内容,并保存完整的来源记录。

系统采用前后端分离架构实现,后端基于 FastAPI 框架和关系数据库完成业务接口开发、权限校验、数据建模和审计记录功能,前端基于 Next.js 框架实现项目工作台、实验笔记管理、资料库管理、知识图谱可视化、AI 知识库和智能生成等功能页面。系统通过 JWT Token 实现用户身份认证,通过四级项目权限体系确保数据访问安全,通过版本管理、审核流程和审计日志保证操作可追溯。实验验证以功能闭环验证、权限隔离测试、知识图谱构建效果评估、问答记录与评价分析以及场景化对照实验为重点。基于以上方法,本文实现并部署了完整的智能电子实验笔记系统。当前演示项目包含 15 条已审核实验笔记、7 份入库资料、177 个图谱实体和 237 条图谱关系,后端 26 个自动化测试用例全部通过。系统在 20 题同题双模式对照实验中完成 40 条问答日志记录和人工评价。结果表明,图谱增强 RAG 在准确率(100%)、可追溯率(100%)和平均评分(4.45/5)上均优于普通项目 RAG(准确率 85%,可追溯率 70%,平均评分 3.90/5),验证了实验知识图谱上下文对问答质量的提升作用。系统能够实现已审核实验记录到图谱构建、资料入库、图谱增强问答、人工评价和审计追溯的完整闭环。

关键词:电子实验笔记;科研数据管理;知识图谱;检索增强生成;固定任务型智能辅助生成;可追溯问答

系统在项目级权限隔离、审核后入图谱的机制保障下,将已审核实验笔记及其附件成功转化为知识图谱实体和关系,并通过融合图谱上下文的检索增强生成技术实现了有来源依据的智能问答。固定任务型智能辅助生成机制为科研人员提供了实验总结、周报等结构化文书整理能力。实验结果表明,本文系统在功能闭环、安全隔离和问答可追溯方面达到了预期目标。系统的自动化测试全部通过,功能闭环完整,权限隔离有效,图谱增强 RAG 在准确率和可追溯率上均优于普通 RAG。

## Abstract

Scientific experimental records are fundamental to experiment reproduction, data traceability, and research output. In academic research groups, a complete experimental study may involve tens to hundreds of experiment records covering multiple experiment types, various reagents and instruments, and repeated validations at different time points. Paper notebooks and general electronic documents can preserve basic experimental information, but they are significantly limited in multi-person project collaboration efficiency, unified attachment archiving, semantic association between experimental knowledge items, project-level data permission isolation, and evidence source tracing for AI-assisted question answering. In project-based research management, experimental records should be transformed into trusted knowledge only after passing a review process, and AI-assisted answers must remain within project boundaries and be supported by verifiable evidence sources. Therefore, the core problem of this thesis is how to transform approved experimental records into traceable structured knowledge under project-level permission constraints and further use this knowledge to support evaluable intelligent question answering with clear evidence provenance.

To address this problem, this thesis designs and implements an intelligent electronic laboratory notebook system for research experiment record management. The system uses projects as the core management unit and supports users, groups, project members, experiment notes, templates, attachments, approval workflows, and audit logs. For knowledge organization, a project-level experimental knowledge graph model is constructed. Projects, notes, users, attachments, experiment types, reagents, instruments, samples, and results are modeled as entities, while semantics such as note inclusion, creator, attachment association, reagent usage, and result generation are modeled as relations. Knowledge graph extraction is triggered only after experiment notes are approved, preventing drafts and unverified records from entering the knowledge base.

For intelligent question answering, this thesis designs a project-level retrieval-augmented generation process enhanced by experimental knowledge graphs. Approved documents are synchronized to the project knowledge base. During question answering, relevant graph relations are retrieved within the current project, and structured graph context is combined with document retrieval results as generation evidence. Each query records the mode, graph hit count, source count, response time, evidence, and manual evaluation, providing a basis for comparing ordinary RAG and graph-enhanced RAG. For experiment summaries, weekly reports, stage reports, and graph overviews, the system adopts fixed-task intelligent generation and stores source notes, source files, and graph relation evidence instead of treating it as an open-ended autonomous agent.

The system adopts a front-end and back-end separated architecture. The back end is implemented with FastAPI and a relational database for REST APIs, user authentication, project-level permission checking, data modeling, and audit logging. The front end is implemented with Next.js and provides pages for project workspace, experiment notes management, document library, knowledge graph visualization, AI knowledge base, and intelligent generation. The system uses JWT Token for user authentication, implements a four-level project permission system for data access control, and ensures operation traceability through version management, approval workflows, and audit logs. The validation focuses on functional closure, permission isolation, knowledge graph construction, query logging, and scenario-based comparative experiment design. The current demonstration project contains 15 approved experiment notes, 7 ingested documents, 177 graph entities, and 237 graph relations, and all 26 backend automated tests pass. The results of a 20-question dual-mode comparative experiment across 40 query logs show that graph-enhanced RAG outperforms plain project RAG in accuracy (100% vs 85%), traceability (100% vs 70%), and average score (4.45/5 vs 3.90/5), validating the contribution of experimental knowledge graph context to question answering quality. The system can form a complete closed loop from approved records to graph construction, document ingestion, graph-enhanced question answering, manual evaluation, and audit tracing. The experimental results verify the system's capability in project-level permission isolation, review-based knowledge graph construction, KG-enhanced question answering with traceable sources, and fixed-task intelligent generation for experiment summary and report writing.

实验结果分析从功能闭环、安全边界、知识图谱构建效果、RAG 对照实验和固定任务型智能辅助生成等多个维度验证了系统的有效性和可用性。后端 26 个自动化测试全部通过,覆盖了知识图谱抽取、RAG 问答、智能生成和权限边界等核心功能模块。知识图谱构建效果显示演示项目中的各类实验对象能够被有效组织和关联,177 个实体和 237 条关系覆盖了九种实体类型和八种关系类型。RAG 对照实验表明图谱增强模式在准确率、可追溯率和平均评分方面均优于普通 RAG 模式,验证了知识图谱上下文对问答质量的提升作用。系统从实验记录到结构化知识再到可追溯问答的完整闭环得到了验证。本文的工作表明,将知识图谱与项目级 RAG 相结合,可以为科研实验记录管理提供一条兼顾知识结构化、问答可追溯和操作安全可控的实现路径。

Keywords: Electronic Laboratory Notebook; Research Data Management; Knowledge Graph; Retrieval-Augmented Generation; Fixed-Task Intelligent Generation; Traceable Question Answering

## 第一章 绪论

### 1.1 研究背景及意义

科研实验活动通常伴随大量过程性记录,包括实验目的、实验条件、试剂耗材、仪器设备、样本信息、实验步骤、结果观察、异常情况和后续分析计划等内容。在生物医学、化学和材料科学等领域,一项完整的实验研究可能涉及数十到数百条实验记录,涵盖多个实验类型、多种试剂和仪器的使用,以及不同时间点的重复验证。实验记录既是科研人员复现实验过程、验证实验结果的基本依据,也是团队内部协作沟通、项目阶段交接、学术论文发表和科研数据审查的重要支撑材料。若实验记录分散在纸质笔记、个人电子文档、即时通讯记录或本地文件夹中,当需要检索特定实验条件、追溯某个结果的来源或汇总一段时间内的实验进展时,会面临明显的效率瓶颈和信息遗漏风险。

电子实验笔记系统通过数字化的方式记录、存储和管理实验过程,能够有效改善纸质实验笔记在检索效率、多人共享和附件统一管理等方面的问题。已有研究和实践表明,电子实验笔记与科研数据管理、数据仓储和开放科学具有紧密联系,能够为科研数据的完整性、可发现性和可复用性提供基础支撑[1-3]。然而,目前多数 ELN 系统主要关注记录和检索功能的数字化实现,将纸质笔记迁移为网页表单或在线文档,并未充分解决实验知识之间缺少语义关联、AI 问答缺乏可核查的来源依据以及不同项目之间的知识权限难以隔离等更深层次的问题。

近年来,大语言模型和检索增强生成技术发展迅速。RAG 通过外部知识检索补充模型参数知识,能够缓解模型知识过时和回答依据不透明的问题[7-9]。知识图谱能够以实体和关系的方式组织领域知识,为结构化检索、关系推理和可视化分析提供支持[5-6]。智能体与工具调用技术则使大语言模型能够围绕固定任务执行检索、整理和生成操作[13-16]。这些技术为电子实验笔记系统从"记录工具"升级为"实验知识管理与智能辅助平台"提供了条件。

因此,本文研究的意义主要体现在三个方面。第一,从科研数据管理角度,系统将实验笔记、附件资料、审核流程和审计日志统一到项目级闭环管理体系中,有助于提升实验记录的完整性、一致性和可追溯性,为科研数据的 FAIR 化管理提供系统层面的支撑。第二,从知识组织角度,系统将实验记录中涉及的试剂、仪器、样本和结果等核心对象抽象为知识图谱实体和关系,使零散的实验记录具备了关联检索和可视化展示的条件,降低了科研人员在大量实验记录中查找特定实验条件的认知负担。第三,从智能辅助角度,系统将项目级 RAG、知识图谱上下文和固定任务型智能辅助生成相结合,使 AI 回答和生成内容具备明确的来源依据,降低了通用大语言模型在科研记录场景中可能产生的不可控风险,为课题组引入 AI 辅助能力提供了一条可控、可追溯的实现路径。

### 1.2 国内外研究现状

#### 1.2.1 电子实验笔记系统研究现状

电子实验笔记系统最初主要用于替代纸质实验笔记,核心功能集中在记录、检索、共享和归档。openBIS ELN-LIMS 将电子实验笔记与实验室信息管理系统结合,强调学术实验室中实验数据、样本、项目和权限的综合管理[2]。近年关于材料合成等领域的研究进一步指出,ELN 不应只是纸质记录的电子化版本,还可以成为科研数据进入计算分析和自动化建议流程的入口[3]。在实验教学场景中,ELN 的实施研究也表明,系统设计需要兼顾记录规范、用户接受度和使用流程[4]。

从现有系统看,ELN 的基础功能已经较为成熟,但在高校或课题组场景中仍存在一些问题:一是实验记录与附件资料常常分开保存,难以形成统一的数据链路;二是审核、归档、作废等过程没有完整留痕,影响后续追溯;三是实验记录中的试剂、仪器、样本和结果等知识通常停留在文本层面,缺少结构化建模;四是系统引入 AI 功能时,容易出现回答来源不清和跨项目知识泄露问题。

#### 1.2.2 大语言模型与 RAG 技术研究现状

RAG 通过将检索结果引入生成过程,使模型能够利用外部知识完成问答、摘要和知识密集型任务[7]。近年来,面向大语言模型的 RAG 研究进一步关注检索粒度、索引构建、重排序、上下文压缩、评价指标和应用工程化等问题[8-9]。Asai 等提出的 Self-RAG 通过自反思机制让模型自主判断是否需要检索以及检索结果的质量[12]。面向图结构知识的 GraphRAG、轻量化 RAG 等研究,则进一步说明检索增强生成正在从单纯文档片段检索向结构化知识融合和生成质量控制方向发展[10-11]。

在科研实验记录管理场景中,RAG 的价值主要体现在两个方面:一方面,它能够让 AI 问答基于项目资料库中的审核资料,而不是只依赖模型自身知识;另一方面,它能够把回答来源展示给用户,提高回答可追溯性。然而,普通 RAG 主要依赖文档片段检索,难以直接表达"某实验使用了哪些试剂""某结果来自哪条实验笔记"等结构化关系。因此,本文在项目级 RAG 基础上进一步引入实验知识图谱上下文。

#### 1.2.3 知识图谱在科研数据管理中的应用现状

知识图谱通过实体、关系和属性组织知识,适合表达复杂对象之间的关联[5]。相关综述从知识表示、知识获取、知识融合和知识应用等角度总结了知识图谱的研究方向[6]。在科研数据管理场景中,知识图谱能够将项目、人员、样本、仪器、实验步骤和结果等对象连接起来,为数据发现、关联检索和知识追溯提供基础。

实验记录中的知识具有明显的项目边界和过程属性。若直接构建全局知识图谱,可能造成不同项目之间的知识混合和权限风险。因此,本文采用项目级知识图谱设计,将 `project_id` 作为实体和关系的隔离维度,并通过实验笔记审核流程控制图谱更新时机,使结构化知识既能服务检索和问答,又不破坏项目权限边界。

#### 1.2.4 智能体与工具调用技术研究现状

智能体相关研究关注大语言模型如何结合推理、行动和外部工具完成任务。ReAct 将推理轨迹与行动过程交替组织,使模型能够在执行任务时调用外部环境并更新中间状态[13]。Toolformer 研究了语言模型学习调用外部工具的能力[14]。面向大语言模型自主智能体的综述进一步总结了规划、记忆、工具使用和任务执行等关键方向[15]。在化学和科研任务中,大语言模型结合外部工具已经被用于辅助实验规划、化学信息查询和自动化研究流程,说明工具增强模型具有科研辅助潜力[16,20]。

在电子实验笔记系统中,智能体不宜被设计成完全开放的自动执行主体。科研记录场景强调可控性和可追溯性,因此本文不研究开放式自主智能体,而是采用固定任务型智能辅助生成设计,限定其任务为实验总结、周报、阶段报告和实验过程图谱概览,并记录生成来源和审计日志,使智能生成结果能够被人工检查。

### 1.3 现有研究存在的问题

结合电子实验笔记、RAG、知识图谱和智能辅助生成研究现状,本文将研究问题集中为一个主问题:在项目级权限边界内,如何把已审核实验记录转化为可追溯的结构化知识,并进一步用于支撑有来源、有评价记录的智能问答。围绕该主问题,现有系统和方法主要存在以下不足。

第一,实验记录的知识结构化不足。普通 ELN 系统更重视记录、检索和附件管理,实验笔记中的试剂、仪器、样本、结果和人员等对象通常仍停留在文本或表单字段中。用户可以查到某条记录,却难以直接回答"某结果来自哪条实验笔记""某实验使用了哪些关键试剂"等关系型问题。

第二,普通 RAG 对实验关系型问题支撑不足。RAG 能够利用文档片段回答资料事实型问题,但实验记录中大量问题依赖实体关系和过程追溯。仅依赖文本相似度检索时,系统可能命中文档片段,却不能稳定提供结构化依据,导致回答虽然可读但来源链条不够清楚。

第三,知识检索与 AI 问答存在项目边界风险。科研项目通常具有不同成员范围和数据敏感性。若搜索、知识图谱、RAG 问答和生成记录未统一绑定项目权限,用户可能访问到无权限项目的笔记、资料、通知或统计信息,从而削弱系统安全性与可信度。

第四,AI 辅助结果缺少可评价闭环。科研记录场景不能只关注生成文本本身,还需要记录回答依据、响应耗时、评价结果和审计日志。缺少这些记录时,系统难以比较普通 RAG 与图谱增强 RAG 的效果,也难以判断生成内容是否适合进入科研汇报或后续整理流程。

### 1.4 论文主要研究内容

本文主要完成以下研究与实现工作。

第一,建立项目级实验记录管理与可信知识沉淀需求模型。本文分析课题组实验记录流程,明确用户、项目、实验笔记、附件资料、审核、权限和审计之间的约束关系,将"已审核记录才能进入知识层"和"所有知识操作必须受项目权限约束"作为后续方法设计前提。

第二,设计面向实验记录的项目级知识图谱构建方法。本文定义项目、实验笔记、人员、附件、实验类型、试剂、仪器、样本和实验结果等实体类型,以及包含笔记、创建者、关联附件、使用试剂、使用仪器、使用样本和产生结果等关系类型,并给出规则与结构化字段结合的轻量抽取流程。

第三,设计审核约束下的可信知识更新机制。系统在草稿创建和草稿更新阶段不抽取图谱,在实验笔记审核通过后自动抽取知识图谱,手动重建也只处理已审核笔记,从而使图谱内容与科研审核流程保持一致。

第四,设计融合知识图谱的项目级 RAG 问答流程。系统将审核通过的资料同步至项目知识库,在问答时结合资料检索结果和项目内图谱上下文,并记录问答模式、来源、图谱命中数、响应耗时和人工评价,为普通 RAG 与图谱增强 RAG 对比提供评价基础。

第五,设计固定任务型智能辅助生成机制。系统支持实验总结、周报、阶段报告和实验过程图谱概览等限定任务,并保存来源实验笔记、来源资料、图谱关系和生成耗时。本文将该部分定位为固定任务型智能辅助生成,不将其扩展表述为完全自主智能体。

第六,实现并验证智能电子实验笔记系统。本文基于前后端分离架构实现系统,并通过自动化测试、权限边界测试、构建测试、运行时 API 冒烟和浏览器关键路径验证系统可用性、安全边界和数据闭环。

### 1.5 论文创新点

本文围绕项目级权限约束下已审核实验记录的结构化知识组织与可追溯问答这一核心问题,在方法设计和系统实现方面的创新性主要体现在以下三个方面。

第一,提出审核约束下的项目级实验知识图谱构建机制。现有知识图谱构建研究通常关注如何从文本中准确抽取实体和关系,而较少考虑在科研记录管理场景中哪些内容可以进入图谱。本文在构建实验知识图谱时,将知识更新与实验笔记的审核状态绑定,草稿和未审核内容不触发图谱抽取,只有审核通过的记录才能进入知识图谱。同时,在实体、关系和抽取记录中保留项目编号和来源信息,使图谱知识具有明确的项目边界和审核流程依据。

第二,提出融合实验知识图谱上下文的可追溯 RAG 问答流程。系统在普通资料检索基础上引入项目内的实体关系上下文作为回答的结构化依据,支持普通项目 RAG 和图谱增强 RAG 两种问答模式的切换。系统在每次问答中统一记录模式标识、资料来源、图谱依据、图谱命中数、响应耗时和人工评价结果,为普通 RAG 与图谱增强 RAG 的比较提供了可复核、可统计的数据基础。

第三,设计面向实验记录整理的固定任务型智能辅助生成机制。与目前研究中常见的开放式自主智能体不同,本文将生成任务限定为实验总结、周报、阶段报告和图谱概览四类可明确定义边界的任务。系统在生成过程中记录来源笔记、来源资料、图谱关系和审计日志,使生成结果能够被人工逐项核查,而不是作为黑箱式的自主决策结果。这种设计既发挥了 AI 在结构化文本生成方面的效率优势,又保留了科研场景中必要的人工审核环节。

### 1.6 论文组织结构

本文共分八章。第一章介绍研究背景、研究现状、存在问题和主要研究内容,明确本文面向的核心问题和解决思路。第二章介绍电子实验笔记、科研数据管理、RAG、知识图谱、智能体和系统开发技术,为后续方法设计和系统实现提供理论基础和技术支撑。第三章分析科研实验记录业务场景和系统需求,从用户角色、功能流程和非功能需求等角度建立系统设计的目标约束。第四章阐述实验知识图谱构建与可信知识管理方法,包括实体关系定义、轻量级抽取流程设计、审核后入图谱的更新机制和可视化关联检索方式。第五章阐述基于知识图谱与 RAG 的智能问答及固定任务型辅助生成方法,包括项目级 RAG 知识库构建流程、图谱增强检索策略设计、权限约束下的问答实现、三层来源追溯机制以及四类固定任务型辅助生成的具体设计。第六章介绍系统架构、模块划分、数据库表设计和关键功能的具体实现,将第四章和第五章的方法映射到后端的 API 接口和前端的展示页面中。第七章给出系统的实验与结果分析,包括评价指标体系建立、功能闭环验证、安全边界测试、知识图谱构建效果评估和普通 RAG 与图谱增强 RAG 的对照实验结果分析。第八章总结本文的工作,对主要创新点进行归纳,分析当前系统的不足并展望未来的改进方向。

## 第二章 相关理论与技术

### 2.1 电子实验笔记与科研数据管理

电子实验笔记是对传统实验笔记的数字化扩展,其核心目标是记录实验过程、保存实验数据、支持团队共享和长期追溯。与普通文档相比,ELN 更强调实验对象、流程状态、附件、版本和审计信息。科研数据管理则关注数据从产生、保存、整理、共享到复用的全生命周期。FAIR 原则提出科研数据应具备可发现、可访问、可互操作和可复用等特征[1],为实验记录系统设计提供了重要参考。

在学术实验室场景中,openBIS ELN-LIMS 将电子实验笔记与实验室信息管理系统相结合,为样本管理、实验流程和数据归档提供了一体化方案[2]。近期研究进一步指出,ELN 不仅可作为实验记录的电子化存储工具,还可以成为科研数据进入计算分析和自动化建议流程的入口[3]。在实验教学领域,Walsh 和 Cho 的研究表明 ELN 系统的实施需要兼顾记录规范性和用户接受度[4]。

本文系统在 ELN 基础上引入项目级资料库、审核入库、知识图谱和 RAG 问答,目的是使实验记录不仅能被保存,还能被检索、关联和解释。系统中的实验笔记采用版本管理,每次内容变更生成新的版本记录并保留历史版本供查阅。附件资料具有上传、审核、同步和归档状态,覆盖文件从上传到入库的完整生命周期。审计日志记录用户的关键操作,包括创建笔记、提交审核、图谱抽取、AI 问答和智能生成等,从而支撑科研数据管理中的完整性和可追溯性要求。

### 2.2 大语言模型与检索增强生成技术

大语言模型通过大规模语料训练获得文本理解和生成能力。Transformer 架构通过自注意力机制提升了序列建模效率[17],大规模预训练语言模型进一步表现出少样本学习能力[18]。相关综述指出,大语言模型在自然语言理解、生成、推理和工具使用方面持续发展,但可靠性、事实性和可控性仍是应用落地的重要问题[19]。在需要特定领域知识支撑的场景中,直接使用通用模型回答问题容易产生事实性错误。

RAG 将外部知识库检索与文本生成结合,是缓解大语言模型幻觉问题的主流方法之一。系统先根据用户问题检索相关文档片段,再将检索结果作为上下文输入生成模型,从而提升回答的事实相关性和可追溯性[7-9]。Trivedi 等将链式思维推理与检索过程交替进行,使模型在多步推理任务中能够动态获取外部知识[21]。Asai 等提出的 Self-RAG 通过自反思机制让模型自主判断是否需要检索以及检索结果的质量,从而减少无关检索和错误信息引入[12]。Yan 等设计的 Corrective RAG 在检索后增加了结果验证和修正步骤,进一步提升了 RAG 系统的鲁棒性[22]。Edge 等的 GraphRAG 和 Guo 等的 LightRAG 通过图结构组织检索结果,说明 RAG 正从单纯文本片段检索向结构化知识融合方向发展[10-11]。

本文采用项目级 RAG 思路,将每个项目的资料库独立同步到外部 Dify 知识库,并在系统内保存资料来源和问答日志,便于后续按模式统计和比较问答效果。

### 2.3 知识图谱与实体关系建模

知识图谱通常由实体、关系和属性构成,用于表示对象之间的语义联系。与纯文本检索相比,知识图谱能够更直接地表达"谁创建了某条笔记""某实验使用了哪些试剂""某结果由哪条笔记产生"等关系。Hogan 等的综述系统总结了知识图谱的定义、构建技术和应用场景[5];Ji 等从知识表示、获取和融合角度全面梳理了知识图谱研究方向[6]。Pan 等系统梳理了大语言模型与知识图谱在知识表示、推理和补全等方向的协同路径,指出知识图谱能够为大语言模型提供结构化先验知识,而大语言模型能够辅助知识图谱的自动构建和扩充[23]。

本文系统使用关系数据库保存项目级知识图谱,包括 `kg_entities`、`kg_relations` 和 `kg_extraction_runs` 三类核心表。在实体建模方面,系统定义项目、实验笔记、用户、附件资料、实验类型、试剂、仪器、样本和实验结果等类型。在关系建模方面,系统定义包含笔记、创建者、关联附件、实验类型、使用试剂、使用仪器、使用样本和产生结果等关系。实体和关系均包含 `project_id` 字段,用于保证知识图谱不会跨项目混合。

### 2.4 智能体与工具调用机制

智能体通常指能够围绕目标执行规划、调用工具和生成结果的软件实体。ReAct 将推理轨迹与行动过程交替组织,使模型能够在执行任务时调用外部环境并更新中间状态[13]。Toolformer 研究了语言模型学习调用外部工具的能力[14]。Wang 等的综述全面总结了大语言模型自主智能体在规划、记忆、工具使用和任务执行等方向的研究进展[15]。Park 等构建的生成式智能体系统在模拟环境中展示了基于记忆和反思的长期行为规划能力,为智能体系统设计提供了新的思路[24]。

在科研场景中,智能辅助系统的应用日益受到关注。Bran 等将大语言模型与化学工具库结合,实现了从文献检索到实验条件推荐的半自动化流程[16]。Boiko 等构建了基于大语言模型的自主化学研究系统,能够在有机合成实验中进行反应条件筛选和结果分析[20]。

然而,在科研记录管理场景中,过度开放的自主任意执行可能带来数据安全和结果不可控风险。因此,本文不采用完全开放式自主执行,而是采用固定任务型智能辅助生成设计。系统预设实验总结、周报、阶段报告和图谱概览四类任务,根据项目内实验笔记、资料和图谱关系生成内容,并将来源信息写入 `agent_generation_runs` 表。这种设计符合科研记录场景的谨慎性要求。智能生成结果可以提高整理效率,但不能替代研究人员判断。因此系统保留生成记录、来源依据和审计日志,使用户能够知道生成内容来自哪些实验笔记和资料。

### 2.5 系统开发相关技术

本文系统采用前后端分离架构。后端使用 FastAPI 提供 REST API,使用 SQLAlchemy 建模数据表,使用关系数据库保存用户、项目、笔记、附件、知识图谱、AI 日志和审计数据。前端使用 Next.js 构建单页式工作台界面,提供登录、项目管理、实验笔记、资料库、知识图谱、AI 知识库和智能生成等功能页面。RAG 能力通过外部 Dify 知识库接口完成资料同步和问答调用。

FastAPI 作为 Python 生态中的异步 Web 框架,具有自动生成 OpenAPI 文档、基于 Pydantic 的请求验证和原生异步支持等特点,适合构建需要与外部 AI 服务进行 HTTP 通信的后端接口。SQLAlchemy 作为 ORM 框架,能够通过声明式映射将 Python 类与数据库表关联,支持多种数据库后端的迁移和操作。Next.js 提供的服务端渲染和静态生成能力有助于提升前端页面的加载性能,其文件系统路由和 API 路由机制便于组织项目结构。Dify 作为开源 LLMOps 平台,提供了知识库管理、检索和对话编排能力,适合快速集成到科研管理系统的问答模块中。

### 2.6 本章小结

本章从六个方面介绍了与本文系统设计相关的理论和技术基础。2.1 节介绍了电子实验笔记和科研数据管理的基本概念,指出 ELN 系统正从简单的数字化记录工具向集成化数据管理平台发展。2.2 节介绍了大语言模型和检索增强生成技术,重点说明了 RAG 的基本架构、Self-RAG 和 Corrective RAG 等改进方法,以及本文采用项目级 RAG 的技术思路。2.3 节介绍了知识图谱的基本概念和实体关系建模方法,以及大语言模型与知识图谱协同发展的最新研究方向。2.4 节介绍了智能体和工具调用机制,分析了开放式自主智能体与固定任务型智能辅助生成的适用场景差异。2.5 节介绍了系统开发所使用的前后端技术和 AI 平台工具。上述理论和技术共同构成本文系统设计的基础:ELN 和科研数据管理提供业务流程框架[1-4],知识图谱综述和 LLM+KG 路线图支撑实验知识的结构化建模[5-6,23],RAG 及其综述支撑外部知识库的引入[7-9],Self-RAG、Corrective RAG 和 GraphRAG 等研究说明 RAG 正向结构化知识融合方向发展[10-12,21-22],固定任务型智能辅助生成提供安全可控的报告整理能力[13-16,20,24],前后端分离架构为系统工程实现提供了技术保障。

## 第三章 面向科研实验记录的需求分析与问题建模

### 3.1 科研实验记录业务场景分析

科研实验记录通常围绕项目展开。在高校课题组中,一个项目通常对应一个独立的研究课题,可能持续数月到数年,涉及多名成员的分工协作。不同成员在项目中承担不同角色:实验人员负责具体的实验操作和记录填写;审核人员负责检查实验记录的真实性和规范性;项目负责人负责整体进度管理和资源配置;管理员负责系统层面的用户和权限维护。

实验人员创建实验笔记时,需要填写实验目的、实验日期、实验类型、实验步骤、使用材料、仪器设备、样本信息和实验结果等内容,并根据需要上传实验图片、原始数据、检测报告或实验协议等附件文件。实验笔记填写完成后提交审核,审核人员对笔记内容进行审查。审核通过后记录进入稳定状态,可作为后续分析和知识提取的可信来源;审核不通过则退回修改,并记录审核意见和版本变更历史。

除实验笔记外,项目还需要管理可作为知识库依据的附件资料,如实验方案、项目背景资料、检测报告和参考资料。这些资料应先经过审核,再同步到项目知识库中,供 AI 问答检索使用。系统还需要保存用户操作日志,便于后续追溯谁在何时创建、审核、同步或查询了相关内容。日志记录的范围包括实验笔记的创建、更新、提交、审核,文件的上传、审核、同步,知识图谱的抽取和重建,AI 问答的发起和评价,以及智能辅助生成任务的执行。

### 3.2 用户角色与权限需求分析

系统用户角色包括管理员、项目负责人、审核人员、普通成员和只读成员。管理员负责全局用户和系统管理。项目负责人拥有项目管理权限。审核人员可以审核实验笔记、资料和 AI 问答评价。普通成员可以创建和编辑实验笔记、上传附件和查看项目内容。只读成员只能查看被授权项目内容,不能修改评价或创建智能辅助生成记录。

项目级权限需求包括读取、写入、审核和管理四类能力。系统必须在实验笔记、资料库、搜索、通知、知识图谱、RAG 问答、问答评价和智能辅助生成等接口中校验项目访问权限,防止用户跨项目访问数据。

| 角色 | 读取项目 | 创建/编辑笔记 | 审核笔记/资料 | 管理成员与项目 | AI 问答评价 | 智能辅助生成 |

| 审核人员 | 是 | 可按授权执行 | 是 | 否 | 是 | 可按授权执行 |
| 普通成员 | 是 | 是 | 否 | 否 | 否 | 是 |
| 只读成员 | 是 | 否 | 否 | 否 | 否 | 否 |

### 3.3 实验笔记、附件资料与项目知识库需求分析

实验笔记应支持创建、编辑、提交、审核、退回、归档和作废等完整的生命周期操作。每次笔记内容变化应形成版本记录,保留变更前后的内容差异和变更人信息。审核动作应保存审核人、审核动作(通过或退回)和审核意见,审核意见支持文本输入以便审核人员指出需要修改的具体问题。

附件资料应支持上传、审核、下载、归档和知识库同步等功能。系统区分两类文件:笔记附件和知识文档。笔记附件用于补充实验记录的原始数据或参考材料,知识文档用于构建项目 AI 知识库。对用于 RAG 的资料,只有审核通过的知识文档才能同步到 Dify 知识库,避免未审核内容进入问答系统。

项目知识库需要具备初始化、资料同步、同步状态查看和问答能力。初始化过程在外部 Dify 服务中创建对应的数据集,同步过程将审核通过的知识文档上传到该数据集。资料同步失败时系统应记录失败原因和错误信息,便于用户排查外部服务配置或网络连接问题。项目成员可以在知识库页面查看当前同步状态,包括待同步数量、已同步数量和失败数量。

### 3.4 AI 辅助实验记录管理需求分析

AI 辅助功能主要包括知识库问答、图谱增强问答、问答评价和智能生成。知识库问答应基于项目资料库中的审核资料回答用户问题,并返回具体的来源资料和片段内容,使用户能够核对回答依据。图谱增强问答应在资料检索基础上加入实验知识图谱上下文,使回答能够参考试剂、仪器、样本和结果之间的结构化关系。

问答评价应允许具备审核或管理权限的用户对回答准确性、可追溯性和评分进行记录。每条问答记录应保存问题、回答、模式标识、图谱命中数、来源数、响应耗时和错误信息,便于后续分析和统计。智能生成应支持实验总结、周报、阶段报告和图谱概览四类固定任务,每类任务限定输入参数范围和输出格式,并保存生成来源笔记、来源资料和图谱关系依据。

### 3.5 系统非功能需求分析

系统非功能需求包括安全性、可追溯性、可维护性和可用性。安全性体现在用户认证机制、JWT Token 管理和项目权限隔离。所有涉及跨项目数据访问的操作必须在后端进行权限校验,前端只展示当前用户可访问的内容。可追溯性体现在实验笔记版本记录、审核记录、问答日志、评价记录、智能辅助生成记录和审计日志的完整保存,支持按项目、用户和时间范围进行检索。

可维护性体现在清晰的模块划分、统一的 API 响应格式和数据库表结构设计。后端按业务模块组织路由和模型,前端按功能页面组织组件和 API 调用。可用性体现在前端工作台能够支持日常实验记录和项目资料管理,关键页面在不同屏幕尺寸下保持布局稳定,用户操作流程符合课题组实际工作习惯。

### 3.6 关键问题建模

根据第一章提出的主问题,本文将系统需要解决的关键问题抽象为"项目边界内的可信知识闭环"。该闭环包含四个连续环节,环环相扣,构成从实验记录产生到 AI 辅助应用的完整数据链路。

第一个环节是可信输入。实验人员在项目中创建实验笔记,经过审核人员审核通过后,实验记录从草稿状态转变为可信的已审核状态。审核流程确保了只有经过确认的实验数据才能进入下游的知识处理环节。

第二个环节是结构化转化。已审核的实验笔记进入知识图谱抽取流程,系统从笔记的结构化字段和正文内容中识别试剂、仪器、样本和结果等实体,并建立它们之间的语义关系。转化后的实体和关系存储在项目级的知识图谱表中,以项目 ID 为隔离维度,确保不同项目之间的知识不互相干扰。

第三个环节是知识支撑问答。当用户在项目中提出问题时,系统首先检索项目资料库中的相关内容,同时根据问题关键词查询知识图谱中的相关关系,将资料检索结果和图谱上下文共同传递给问答引擎,最终生成有来源依据的回答。

第四个环节是结果回存。问答结果、图谱依据、资料来源、响应耗时和人工评价等信息都保存到数据库中,形成可追溯的 AI 操作记录。这些记录既服务于后续的效果分析,也为审计追溯提供数据支撑。

后续第四章、第五章和第七章分别对应该闭环的知识图谱构建方法、问答方法和实验验证,而不是将各功能模块孤立描述。

#### 3.6.1 实验记录非结构化问题

实验笔记内容往往包含自由文本、表格字段和附件资料。若不进行结构化处理,系统只能按关键词检索文本,难以表达实验对象之间的关系。本文将实验记录中的关键对象抽象为实体,将实验过程中的语义联系抽象为关系,使实验记录具备可关联检索能力。

#### 3.6.2 项目知识权限隔离问题

科研项目之间可能存在不同权限边界。本文在实体、关系、资料、问答日志和生成记录中均保留 `project_id`,并在接口层进行项目访问校验,使知识图谱、RAG 和智能辅助生成均限定在当前项目范围内。

#### 3.6.3 实验知识关联不足问题

普通实验笔记系统通常只展示笔记列表和附件列表,用户难以从整体上观察实验关系。本文通过知识图谱页面展示实体统计、关系图、筛选器和实体详情,使用户能够从项目、笔记、人员、试剂、仪器、样本和结果等角度查看实验知识关联。

#### 3.6.4 AI 回答可信性与可追溯问题

普通 AI 问答如果只返回文本答案,用户难以判断答案是否依据项目资料。本文系统在问答结果中保存资料来源、图谱依据、响应耗时和人工评价,并将相关操作写入审计日志,从而增强回答可信性和可追溯性。

### 3.7 本章小结

本章从科研实验记录的实际业务流程出发,首先分析了科研课题组中项目管理和实验记录的基本工作模式,明确了管理员、项目负责人、审核人员、普通成员和只读成员五类用户角色及其对应的读取、写入、审核和管理四级权限需求。随后对实验笔记的全生命周期管理、附件资料的分类管理和项目知识库的构建等核心功能进行了需求分析,明确了基础业务功能的范围和流程约束。在 AI 辅助功能方面,分析了知识库问答、图谱增强问答、问答评价和固定任务型智能辅助生成的输入输出要求。在非功能需求方面,从安全性、可追溯性、可维护性和可用性四个角度进行了分析。最后对非结构化记录、项目权限隔离、知识关联不足和 AI 回答可追溯性四个关键问题进行了建模,提出了项目边界内可信知识闭环的设计思路。上述需求分析和问题建模为后续知识图谱方法、RAG 方法和系统实现提供了设计目标和约束条件。

## 第四章 实验知识图谱构建与可信知识管理方法

在完成了第三章的需求分析和关键问题建模后,本章进入方法设计的第一部分:实验知识图谱构建与可信知识管理方法。第三章的分析表明,当前 ELN 系统在实验对象的结构化建模方面存在不足,实验笔记中的试剂、仪器、样本和结果等关键信息通常以文本形式散落在记录中,难以被直接检索、关联和利用。本章的核心思路是将这些实验对象以实体和关系的形式进行结构化建模,并建立实体关系与实验笔记审核流程之间的绑定关系,实现在项目权限约束下的可信知识沉淀,为后续的图谱增强问答和智能辅助生成提供结构化的知识基础。

### 4.1 实验知识图谱总体设计

本文构建的实验知识图谱以项目为边界,以实验笔记为核心节点,将实验记录涉及的对象和关系组织起来。图谱构建遵循三项原则。

第一,项目隔离原则。所有实体和关系均绑定 `project_id`,图谱查询和可视化只在当前项目范围内进行。第二,审核后入图谱原则。实验笔记草稿和未审核内容不进入图谱,只有审核通过的笔记才触发实体关系抽取。第三,可追溯原则。图谱关系保留来源类型、来源编号、置信度和属性信息,使用户能够追踪关系来自哪条实验笔记或附件。

### 4.2 实验记录实体定义

系统定义的实体类型包括项目、实验笔记、实验人员、附件资料、实验类型、试剂、仪器、样本和实验结果。项目实体表示科研项目本身。实验笔记实体表示项目下的具体实验记录。实验人员实体表示笔记创建者或参与者。附件资料实体表示与笔记或项目资料库相关的文件。实验类型实体表示实验分类。试剂、仪器、样本和实验结果实体来自笔记结构化字段或文本内容抽取。

实体表 `kg_entities` 保存实体编号、项目编号、实体类型、显示名称、归一化名称、自然键、来源类型、来源编号和属性 JSON。系统通过项目编号和自然键设置唯一约束,避免同一项目内重复创建等价实体。

表 4-1 给出了系统当前定义的实验知识图谱实体类型。

| 实体类型 | 系统标识 | 含义 | 主要来源 |
| --- | --- | --- | --- |
| 项目 | `project` | 科研项目或实验项目 | 项目表 |
| 实验笔记 | `note` | 项目下的单条实验记录 | 实验笔记表 |
| 用户 | `user` | 实验记录创建者或相关人员 | 用户表 |
| 附件资料 | `file` | 实验附件或项目知识文档 | 文件表 |
| 实验类型 | `experiment_type` | PCR、Western Blot、细胞培养等分类 | 笔记字段 |
| 试剂 | `reagent` | 实验中使用的试剂、材料或药品 | 结构化字段或文本抽取 |
| 仪器 | `instrument` | 实验中使用的仪器或设备 | 结构化字段或文本抽取 |
| 样本 | `sample` | 实验样本、样品或处理组 | 结构化字段或文本抽取 |
| 实验结果 | `result` | 实验观察、结果或结论 | 结构化字段或文本抽取 |

### 4.3 实验知识关系定义

系统定义的关系类型包括包含笔记、创建者、关联附件、实验类型、使用试剂、使用仪器、使用样本和产生结果。关系表 `kg_relations` 保存项目编号、源实体编号、目标实体编号、关系类型、来源类型、来源编号、置信度和属性 JSON。系统通过项目编号、源实体、目标实体和关系类型设置唯一约束,避免重复关系。

例如,一条审核通过的实验笔记会形成如下关系:项目实体通过"包含笔记"关系指向实验笔记实体;实验笔记实体通过"创建者"关系指向用户实体;若笔记关联附件,则通过"关联附件"关系指向附件资料实体;若笔记内容中记录了试剂、仪器、样本和结果,则分别形成"使用试剂""使用仪器""使用样本"和"产生结果"关系。

表 4-2 给出了系统当前定义的实验知识关系类型。

| 关系类型 | 系统标识 | 源实体 | 目标实体 | 含义 |
| --- | --- | --- | --- | --- |
| 包含笔记 | `has_note` | 项目 | 实验笔记 | 项目下包含某条实验笔记 |
| 创建者 | `created_by` | 实验笔记 | 用户 | 实验笔记由某用户创建 |
| 关联附件 | `has_attachment` | 实验笔记 | 附件资料 | 笔记关联某个附件或资料 |
| 实验类型 | `has_experiment_type` | 实验笔记 | 实验类型 | 笔记属于某类实验 |
| 使用试剂 | `uses_reagent` | 实验笔记 | 试剂 | 实验过程中使用某种试剂 |
| 使用仪器 | `uses_instrument` | 实验笔记 | 仪器 | 实验过程中使用某种仪器 |
| 使用样本 | `uses_sample` | 实验笔记 | 样本 | 实验过程中使用某类样本 |
| 产生结果 | `produces_result` | 实验笔记 | 实验结果 | 实验笔记产生某项结果或结论 |

### 4.4 基于实验笔记内容的实体关系抽取方法

系统采用"结构化字段优先、规则抽取补充、来源记录保留"的轻量实体关系抽取方法。该方法的输入为已审核实验笔记、当前版本内容 JSON、笔记固定字段和关联附件;输出为项目内实体集合、关系集合和一次抽取运行记录。抽取过程分为四步。

第一,基础实体生成。系统首先根据项目、实验笔记、创建者、实验类型和关联附件生成项目实体、笔记实体、用户实体、实验类型实体和附件实体,并建立"包含笔记""创建者""实验类型"和"关联附件"等基础关系。这部分信息来自数据库结构化字段,稳定性较高。

第二,实验对象抽取。对于实验笔记固定字段和内容 JSON,系统根据字段名识别试剂、仪器、样本和结果等类别;对于自由文本,系统使用中英文关键词模式识别"试剂""材料""仪器""设备""样本""结果""观察""结论"等段落或短语,并按逗号、顿号、分号和换行符拆分术语。

第三,术语归一化与去重。系统对抽取得到的术语进行空白字符清理、大小写归一化和符号规整,并以"项目编号、实体类型、归一化名称"构造自然键。相同项目内自然键相同的实体只保留一份,避免同一试剂或仪器在多条笔记中重复创建。

第四,关系写入与抽取记录。系统将实验笔记实体分别连接到试剂、仪器、样本和结果实体,形成"使用试剂""使用仪器""使用样本"和"产生结果"等关系。每条关系保留项目编号、来源类型、来源编号、置信度和属性信息;每次抽取记录实体数、关系数、运行状态和消息,便于后续复核。

本文没有将该方法表述为通用深度语义抽取模型。其优势在于规则清晰、结果可解释、与审核流程和项目权限容易结合,适用于实验笔记中常见的半结构化字段和规范化记录。其局限在于对长篇自由文本、隐含关系和复杂同义表达识别能力有限,因此第七章将图谱构建效果限定为演示项目中的结构化知识组织能力,而不扩大为通用自然语言信息抽取能力。

### 4.5 面向项目权限的知识图谱更新机制

系统在实验笔记生命周期中严格控制图谱更新时机,确保只有经过审核确认的实验记录才能进入知识图谱。具体规则如下。第一,草稿创建和草稿更新阶段不自动抽取图谱,草稿内容可能包含错误、临时假设或未完成的实验记录,不应作为知识来源。第二,笔记提交后进入审核流程,在审核完成前图谱不会发生变化。第三,审核通过后系统自动调用知识图谱服务抽取实体和关系;若项目配置为免审模式,则笔记提交即视为通过时触发抽取。第四,手动触发抽取和项目图谱重建接口也只处理已审核笔记,对未审核笔记返回错误提示。

该机制避免了未确认实验记录进入知识图谱。对于科研场景而言,草稿内容可能包含错误、临时假设或未完成实验,若提前进入图谱,可能误导后续的 RAG 问答结果和统计分析。因此,审核后入图谱是本文可信知识管理的重要设计,也是区别于普通知识图谱系统的主要特征之一。

### 4.6 资料审核与知识入库机制

项目资料库中的知识文档需要先经过审核,审核通过后才能同步到 Dify 知识库,确保 AI 问答系统使用的资料是经过项目负责人或审核人员确认的。系统为资料设置上传、审核通过、驳回、归档等状态,并为知识库同步设置待审核、待同步、已同步和失败等状态。

同步过程会记录外部 Dify 系统的文档编号和同步结果,包括成功和失败两种情况。失败时同步记录会保留错误信息,方便用户排查外部服务配置或网络连接问题。问答过程中,Dify 返回的来源信息通过文档编号映射回系统内的文件记录,从而在前端展示具体的资料来源文件名称和片段内容。这种设计保证了 AI 问答的资料来源可追溯到经过审核的项目资料文件。

### 4.7 实验知识图谱可视化与关联检索

前端知识图谱页面是系统可视化展示实验知识关联的核心界面。页面顶部展示实体总数、关系总数和各类型实体的数量统计。页面主体区域以 SVG 方式绘制关系图,实体类型以不同颜色的节点表示,关系以带标签的有向边表示。用户可以通过实体类型筛选器和关系类型筛选器控制图谱的显示范围,也可以点击具体节点查看实体的详细属性、来源信息和关联关系列表,并可以从来源为实验笔记的实体直接跳转到对应的实验笔记详情页面。该页面既服务于用户理解项目的实验知识组织结构,也为论文中知识图谱构建效果的展示提供了直接的截图材料。

在关联检索方面,系统实现了一种基于关键词和关系类型提示词的轻量级图谱上下文检索方法。该方法首先对用户问题进行分词,提取试剂、仪器、样本、结果、实验类型等领域的核心关键词;然后结合预定义的关系类型提示词映射表,对项目内所有图谱关系进行评分;最后选取得分排在前 N 位的关系作为图谱上下文,格式化为结构化的提示文本,传递给 RAG 问答模块作为生成依据。

系统知识图谱页面可作为图谱构建结果展示图,建议在论文定稿时插入"图 7-1 实验知识图谱可视化界面",对应截图文件为 `docs/user-guide-assets/06-knowledge-graph.png`。

本章围绕项目级实验知识图谱的构建方法展开设计。在总体设计部分,给出了项目隔离、审核后入图谱和可追溯三项核心原则,明确了图谱构建的约束条件和质量要求。在实体定义部分,定义了项目、实验笔记、用户、附件资料、实验类型、试剂、仪器、样本和实验结果九类实体类型,每类实体给出其系统标识、业务含义和主要数据来源。在关系定义部分,定义了包含笔记、创建者、关联附件、实验类型、使用试剂、使用仪器、使用样本和产生结果八类关系类型,每类关系给出源实体、目标实体和业务含义。在抽取方法部分,提出了结构化字段优先提取基础实体、规则抽取补充实验对象术语、术语归一化去重避免冗余以及来源记录保留确保可追溯的四步轻量抽取流程,并明确了该方法在处理自由文本时与深度学习方法的差距。在更新机制部分,设计了审核后入图谱的触发规则,确保只有通过审核的实验笔记才能进入知识图谱。在可视化设计部分,介绍了前端知识图谱页面的实体统计、关系图、筛选器和实体详情面板等交互功能。本章方法为第五章的图谱增强 RAG 和固定任务型智能辅助生成提供了结构化的知识基础。

## 第五章 基于知识图谱与 RAG 的智能问答及固定任务型辅助生成方法

第四章构建了项目级的实验知识图谱,通过九类实体和八类关系的结构化建模,使已审核的实验记录具备了可检索、可关联的知识组织能力。本章在第四章的基础上进一步设计智能问答和辅助生成方法,解决如何将结构化知识应用于实际科研信息查询和文书整理的问题。具体包括项目级 RAG 知识库的构建和资料同步方法、融合图谱关系的检索增强策略、权限约束下的问答执行流程、三层来源追溯机制以及四类固定任务型辅助生成的设计,使实验知识图谱不仅是一种静态的知识组织方式,更能够动态地服务于科研人员的日常信息获取和汇报材料整理需求。

### 5.1 项目级 RAG 知识库构建方法

系统为每个项目初始化独立的 Dify 知识库数据集。项目资料库中审核通过的知识文档可同步至该数据集,系统保存同步状态和外部文档编号。用户在项目内提出问题时,系统只访问当前项目绑定的数据集,避免跨项目资料混合。

项目级 RAG 流程包括:用户提交问题;系统校验项目访问权限;系统检查项目知识库是否初始化;系统调用外部知识库完成检索与生成;系统解析回答、会话编号和来源片段;系统将问答日志、来源资料和响应耗时保存到数据库。

### 5.2 融合知识图谱的检索增强策略

普通 RAG 主要根据文本相似度检索资料片段,适合回答资料内容型问题。对于实验关系型问题,本文引入知识图谱上下文。系统根据问题在项目图谱中检索相关关系,并将关系格式化为文本,例如"实验笔记 A --使用试剂--> 试剂 B"。随后,系统把图谱上下文和资料检索结果共同传入生成模型。

该策略的核心作用不是替代文档检索,而是补充结构化关系。实验笔记中的试剂、仪器、样本和结果关系经过图谱抽取后,可以作为额外依据帮助模型组织回答。系统同时在问答结果中展示图谱依据和资料来源,使用户能够区分答案来自结构化图谱还是资料片段。

### 5.3 权限约束下的智能问答流程

智能问答接口从用户请求到结果返回的完整流程包括以下步骤。第一步,校验用户是否拥有当前项目的读取权限。若用户无权限,系统直接返回 403 拒绝访问。第二步,检查项目 RAG 数据集是否已初始化。若项目未初始化,系统返回 409 冲突提示,引导用户先完成知识库初始化操作。第三步,根据用户选择的问答模式决定是否检索图谱上下文。若用户选择图谱增强 RAG 模式但项目当前没有可用的图谱上下文,系统返回提示信息,避免在缺少结构化依据时伪装为图谱增强回答。第四步,调用 Dify 聊天接口完成问答,记录响应结果和耗时。第五步,将问答记录写入数据库,并将操作写入审计日志。

问答完成后,系统将完整的问答信息写入持久化存储。写入信息包括问题原文、回答内容、RAG 模式标识、图谱命中数量、资料来源数量、响应耗时毫秒数、图谱上下文 JSON 结构、来源资料 JSON 结构、会话编号和错误信息等。这些信息统一保存在 `ai_query_logs` 表中,为后续的问答统计和效果分析提供数据基础。同时,系统将问答操作写入审计日志,记录操作人、项目编号、问答模式标识和对应的查询日志编号,便于管理员追溯 AI 问答的使用情况。

### 5.4 引用来源与回答可追溯机制

系统的可追溯机制包括三个层次,分别对应不同的数据来源和可信度级别。

第一层,资料来源层。问答结果的前端展示包含来源文件编号、文件名、外部 Dify 文档编号和具体的片段内容。用户可以直接跳转到来源文件查看完整内容,核实回答依据。这一层适用于基于资料检索的普通 RAG 模式。

第二层,图谱依据层。图谱增强 RAG 模式在资料来源基础上额外展示图谱关系信息,包括关系编号、关系类型、源实体名称、目标实体名称和关系置信度。用户可以看到回答中的结构化依据来自哪些实体关系对,例如"PCR 条件优化实验 --使用试剂--> Taq DNA Polymerase"。

第三层,评价层。具备审核或管理权限的用户可以对问答结果进行评价,包括评分(1-5 分)、是否准确、是否可追溯和评价备注。评价数据保存在 `ai_query_evaluations` 表中,通过唯一约束保证每条问答日志只能有一条对应的评价记录。评价接口需要审核或管理权限,只读成员不能提交评价,从而避免普通查看人员影响系统评价指标的统计结果。

### 5.5 面向实验笔记的固定任务型辅助生成设计

#### 5.5.1 实验笔记结构化整理任务

实验笔记结构化整理任务用于将分散的实验记录字段整理为更清晰的摘要内容。其输入包括项目编号、时间范围、实验类型和相关笔记。输出包括整理标题、正文和来源笔记编号。系统保存生成记录,便于用户回看和人工修改。该任务适合在实验项目阶段性完成后,由项目负责人或审核人员触发,用于快速梳理一段时间内的实验进展。

#### 5.5.2 实验总结与周报生成任务

实验总结与周报生成任务面向周期性科研汇报需求。系统根据用户选择的日期范围汇总项目内实验笔记、资料和图谱关系,生成实验进展、主要结果、问题和后续计划。生成内容不直接覆盖原始记录,而是作为辅助草稿展示,用户可以根据实际情况编辑和调整。每周的实验周报可以帮助课题组在组会前快速整理实验进展,减少手动汇总的工作量。

#### 5.5.3 实验知识图谱概览生成任务

实验知识图谱概览生成任务用于生成项目实验过程图谱说明。系统根据当前项目图谱关系生成文字说明,帮助用户理解项目中实验类型、关键试剂、仪器、样本和结果之间的联系。该能力与知识图谱页面配合,用于项目复盘和论文展示。例如,项目负责人可以使用图谱概览功能快速了解项目中涉及的所有实验类型和试剂使用情况,为下一步实验计划提供参考。

### 5.6 基于工具调用/MCP 的辅助生成机制

本文系统目前采用固定任务 API 形式实现辅助生成能力。固定任务方式将四类任务(实验总结、周报、阶段报告和图谱概览)的处理逻辑封装在服务端,通过统一的 API 接口暴露给前端。每次生成任务接收任务类型、日期范围等参数,从数据库中检索已审核的实验笔记、资料文件和知识图谱关系,然后按模板生成结构化的文本输出。

与完全开放式工具调用相比,固定任务方式具有以下优势。第一,可控性强,生成任务的范围和输入参数由系统预设,避免了模型自主选择工具可能带来的不可预期行为。第二,可追溯性好,每次生成的来源笔记、来源文件和图谱关系都保存在数据库中,用户可以逐项核对生成内容是否准确。第三,权限边界清晰,生成接口直接复用项目权限校验逻辑,不需要额外的工具调用授权机制。

系统在后续扩展中可接入 MCP 或其他工具调用协议,将资料检索、图谱查询、实验笔记读取和报告生成封装为可调用工具,但仍应保留项目权限校验和生成来源记录。

### 5.7 本章小结

本章围绕基于知识图谱和 RAG 的智能问答及固定任务型辅助生成方法展开设计。在项目级 RAG 知识库构建方面,设计了基于项目隔离的数据集初始化和资料同步流程,确保不同项目的资料互不干扰。在图谱增强检索方面,提出了在普通资料检索基础上引入结构化图谱上下文作为额外生成依据的策略,并详细说明了基于关键词和关系提示词的图谱关系评分筛选和格式化方法。在权限约束方面,描述了问答接口从用户身份校验、项目权限校验、知识库状态检查到问答模式选择的完整流程,确保每一步操作都在项目权限边界内完成。在来源可追溯方面,设计了资料来源、图谱依据和人工评价三个层次的追溯机制,使问答结果具备可核查的依据链。在固定任务型辅助生成方面,分别介绍了实验总结、周报、阶段报告和图谱概览四类任务的输入参数范围、模板化处理逻辑和结构化输出格式,并说明了生成结果的来源记录保存方式。本章方法使系统能够在项目资料和实验图谱基础上提供可控、可追溯的智能问答与生成能力,项目级知识库隔离保证了跨项目数据安全,图谱增强检索提升了关系型问题的回答质量,固定任务设计兼顾了实用性和科研场景对结果可复核的严格要求。

## 第六章 智能电子实验笔记系统设计与实现

第四章和第五章分别阐述了实验知识图谱构建方法以及基于图谱的智能问答和辅助生成方法。本章从系统实现的角度,说明这些方法具体如何映射到后端的模块划分、数据库表结构、API 接口设计和前端的页面组织中,避免重复展开方法原理部分已经说明的内容。

### 6.1 系统架构设计

系统采用前后端分离架构。前端基于 Next.js 框架提供用户交互界面,后端基于 FastAPI 框架提供 RESTful 业务 API,关系数据库保存用户、项目、笔记、附件、知识图谱、AI 日志和审计等业务数据,外部 Dify 服务提供项目级知识库管理和 RAG 问答能力。整体架构从下到上包括用户认证层、项目业务层、实验笔记层、资料库层、知识图谱层、AI 问答层、智能辅助生成层和审计层,各层之间通过 API 接口进行数据交互,上层依赖下层的服务能力。

后端核心目录按职责划分为 API、模型、模式和服务四个主要部分。API 目录按业务模块组织路由文件,每个路由文件包含对应的请求处理函数和权限校验依赖注入;模型目录定义 SQLAlchemy 数据表映射类,包含字段定义、约束关系和索引配置;模式目录定义 Pydantic 请求和响应数据模型,用于 API 请求验证和响应序列化;服务目录封装知识图谱抽取、Dify API 调用、审计日志写入、文本搜索和报告生成等核心业务逻辑。前端核心页面包括登录认证页、项目工作台概览页、实验笔记管理页、资料库管理页、知识图谱可视化页、AI 知识库问答页、智能生成页和系统管理配置页。

系统主要界面建议在定稿中选取项目工作台、实验笔记、资料库与问答评价、知识图谱、智能生成和项目日志等截图作为图 6-2 至图 7-3。截图来源和建议编号见《论文图表与截图清单》。

| AI 问答 | `ai_query_logs`、`ai_query_evaluations` | 保存问答日志、来源依据和人工评价 |
| 智能辅助生成 | `agent_generation_runs` | 保存总结、周报、阶段报告和图谱概览生成记录 |
| 审计追溯 | `audit_logs` | 保存关键业务操作和追溯信息 |

### 6.4 用户与权限模块实现

系统通过登录接口完成用户身份认证,在登录成功后返回 JWT Token。后续每次 API 请求在依赖层解析 Token 获取当前用户信息。项目访问权限通过 `ProjectMember` 表中的项目-成员关系和角色权限字段计算。系统将权限抽象为四个等级:读取(can_read)、写入(can_write)、审核(can_review)和管理(can_manage)。

在接口实现层面,权限校验通过 FastAPI 的依赖注入机制完成。`require_project_access` 函数负责校验读取权限,`can_write_project` 函数校验写入权限,`can_review_project` 和 `can_manage_project` 分别校验审核和管理权限。这些校验函数被注入到对应接口的路由装饰器中,确保每个接口在执行业务逻辑前完成权限检查。例如,实验笔记创建接口需要写入权限,知识图谱手动抽取和问答评价提交需要审核或管理权限,项目成员配置需要管理权限。

### 6.5 项目与实验笔记模块实现

项目模块支持项目基本信息的创建和编辑、项目成员的添加和移除、成员角色的分配和修改。项目创建时自动将创建者设置为项目负责人,后续可以添加其他成员并分配不同角色。

实验笔记模块支持完整的生命周期状态流转,包括草稿、提交审核、审核通过、退回、归档和作废六个状态。系统在笔记内容变化时自动生成版本记录,保存变更前后的字段内容和变更说明。审核动作发生时,系统同时写入 `note_approvals` 审核表和 `audit_logs` 审计表。审核通过后,系统自动调用 KnowledgeGraphService 的 extract_note 方法触发知识图谱抽取,将当前审核通过的版本中的结构化字段和文本内容转化为项目图谱实体和关系。

### 6.6 附件资料与审核模块实现

附件资料分为笔记附件和知识文档两类,分别服务于不同的业务场景。笔记附件用于补充实验记录的原始数据或参考图片,与特定的实验笔记关联;知识文档用于构建项目 RAG 知识库,独立于实验笔记,属于项目级别的共享资料。

文件上传后,系统保存原始文件名、存储路径、文件类型、文件大小、文件哈希值、审核状态和知识同步状态等字段。知识文档需要经过审核人员审核通过后,才能进入待同步状态。审核通过的知识文档可以由具备管理权限的用户手动触发同步操作,将文件上传到 Dify 知识库。同步到 Dify 失败时,系统在同步记录中保存错误信息,并在文件记录中标记失败状态,同时写入审计日志以便管理员排查问题。

资料库与 AI 问答评价界面能够同时展示资料审核、知识库同步、问答记录和人工评价,建议作为图 6-5 插入本节或第 6.8 节。

### 6.7 知识图谱模块实现

知识图谱模块对应第四章提出的项目级知识图谱方法,主要实现实体关系抽取、更新和查询三个核心功能。

实体关系抽取服务(KnowledgeGraphService)的 extract_note 方法接收一条已审核的实验笔记作为输入,按以下步骤完成抽取。第一步,创建项目实体和当前笔记实体,确保这两个基础实体已在图谱中存在。第二步,创建笔记与项目之间的"包含笔记"关系、笔记与创建者之间的"创建者"关系、笔记与实验类型之间的"实验类型"关系,以及笔记与关联附件之间的"关联附件"关系。第三步,从当前笔记版本的结构化字段和正文内容中提取试剂、仪器、样本和结果等术语,经过名称归一化和去重后创建对应的实体,并建立"使用试剂""使用仪器""使用样本"和"产生结果"等关系。第四步,记录本次抽取运行的状态、抽取实体数、抽取关系数和处理消息,保存到 `kg_extraction_runs` 表。

图谱查询接口返回项目内所有实体和关系,前端使用 SVG 可视化方式展示图谱视图,支持实体类型筛选、关系类型筛选和节点点击查看详情。图谱上下文检索方法根据用户问题中的关键词和预定义的关系类型提示词,对项目内图谱关系进行评分排序,选取得分较高的关系作为 RAG 问答的图谱上下文输入。

### 6.8 AI 问答与智能辅助生成模块实现

RAG 模块对应第五章提出的项目级 RAG 与图谱增强问答流程,主要功能包括项目知识库初始化、资料同步、问答执行、问答日志记录、问答统计和评价管理。

项目知识库初始化接口在 Dify 服务中创建对应的数据集,并将数据集 ID 保存在本地的 `project_rag_datasets` 表中。资料同步接口将审核通过的知识文档上传到 Dify 数据集,并记录同步状态和外部文档 ID。问答执行接口支持普通项目 RAG 和图谱增强 RAG 两种模式。普通项目 RAG 模式直接调用 Dify 的聊天接口,基于项目资料库回答问题。图谱增强 RAG 模式先调用 KnowledgeGraphService 的 find_relevant_context 方法检索项目内相关图谱关系,将图谱上下文格式化为提示文本后与用户问题一起传入 Dify 聊天接口。

问答完成后,系统将完整的问答记录保存到 `ai_query_logs` 表,包括问题、回答、模式、图谱命中数、来源数、响应耗时和来源依据等。系统同时提供按项目查看问答历史和统计指标的接口,以及提交问答评价的接口。

智能辅助生成模块支持实验总结、周报、阶段报告和图谱概览四类固定任务,由 AgentGenerationService 统一处理。生成接口要求用户具备项目写入权限,只读成员可以查看生成历史但不能创建新记录。生成过程从数据库中检索已审核实验笔记、资料文件和知识图谱关系,按任务类型生成结构化的文本内容。生成结果保存标题、正文、来源笔记 ID 列表、来源资料 ID 列表、来源图谱关系 ID 列表、任务状态和响应耗时,确保生成结果的可追溯性。

### 6.9 安全与审计追溯实现

系统安全设计重点包括认证、项目隔离、权限分级和审计追踪。用户认证通过 JWT Token 实现,每次请求在 API 依赖层解析当前用户信息。项目相关接口通过 `project_id` 校验用户访问权限,分为读取、写入、审核和管理四个等级。全局搜索按当前用户可访问项目范围过滤搜索结果,防止信息泄露。通知接口按项目权限读取和发布,用户只能收到自己有权限项目的通知。仪表盘对管理员展示全局统计,对普通用户只展示其可访问项目的汇总信息。

审计日志记录操作人、项目、动作、目标类型、目标编号、详情、IP 地址、用户代理和操作时间。关键操作如知识图谱抽取、RAG 问答、智能辅助生成、问答评价等都会被写入审计日志。审计日志的数据结构支持按项目、用户、动作类型和时间范围进行筛选,便于管理员在需要时追溯特定操作的完整记录。

在数据层面,系统的审计追溯分为三个层次。第一层是业务数据本身,实验笔记的版本表记录了每次内容变更,审核表记录了每次审核动作。第二层是 AI 操作日志,`ai_query_logs` 和 `agent_generation_runs` 记录了 AI 相关操作的输入、输出和来源。第三层是通用审计日志,`audit_logs` 记录了系统层面的关键操作。这三个层次相互补充,共同构成完整的可追溯体系。

项目日志页面可用于展示审计追溯效果,建议作为图 7-3 插入第 7.7 节,说明 AI 查询、评价和智能辅助生成均具有日志记录。

### 7.1 实验目标与评价指标

本章实验围绕第三章提出的"项目边界内可信知识闭环"展开,重点验证四个问题:第一,系统能否完成实验笔记审核、资料入库、图谱构建、问答记录和审计追溯流程;第二,项目权限是否能够约束搜索、通知、RAG、评价和固定任务生成等关键接口;第三,已审核实验记录是否能够被转化为可查看、可追溯的实体关系;第四,系统是否具备普通 RAG 与图谱增强 RAG 对照实验所需的数据记录和评价指标。

为避免只做功能罗列,本文将评价指标划分为功能闭环指标、安全边界指标、知识图谱指标、问答评价指标和场景化验证指标,如表 7-1 所示。

| 指标类别 | 指标 | 计算或判定方式 | 数据来源 |
| --- | --- | --- | --- |
| 功能闭环 | 关键流程通过情况 | 登录、项目访问、笔记审核、资料同步、图谱展示、问答记录、评价和审计日志均可完成 | 自动化测试、浏览器冒烟、运行时 API |
| 安全边界 | 无权限访问拦截情况 | 无权限搜索、项目通知、RAG 查询、问答评价、生成任务返回 403 或无数据 | 后端权限测试 |

| 问答评价 | 准确率、可追溯率、平均评分 | 人工评价中准确、可追溯样本占比和平均分 | `ai_query_logs`、`ai_query_evaluations` |
| 问答证据 | 平均来源数、平均图谱命中数 | `source_count` 与 `graph_hit_count` 的均值 | 问答日志 |

其中,RAG 对照实验的核心量化指标定义如下:

```text
准确率 = 准确回答数 / 已评价回答数
可追溯率 = 可追溯回答数 / 已评价回答数
平均评分 = 评分总和 / 已评价回答数
平均来源数 = 来源数量总和 / 问答次数
平均图谱命中数 = 图谱命中数总和 / 问答次数
平均响应耗时 = 响应耗时总和 / 问答次数
```

从构建机制看,图谱实体和关系来自审核通过的实验笔记及其附件,避免了草稿内容进入图谱。图谱页面支持实体类型和关系类型筛选,用户可以查看节点详情和关系明细。这说明系统能够把演示项目中的实验记录从线性文本组织为可视化的关联结构,为后续图谱增强问答提供结构化上下文。

同时,本文对图谱抽取效果作出限定:当前抽取方法主要依赖结构化字段和规则,适合处理实验笔记中相对规范的试剂、仪器、样本和结果字段。对于自由文本中的隐含关系、复杂同义表达和长句推理,当前方法仍可能漏抽或误抽。因此,第七章不将图谱构建结果解释为通用自然语言抽取效果,而只证明系统具备基于已审核实验记录构建项目级知识图谱的闭环能力。

知识图谱构建效果可通过图 7-1 展示。该图应突出实体统计、关系图、筛选器和实体详情面板,使读者能够直观看到实验记录被组织为实体关系结构。

### 7.5 普通 RAG 与图谱增强 RAG 对照实验设计

系统支持普通项目 RAG 和图谱增强 RAG 两类模式。普通 RAG 依赖项目资料库检索结果,图谱增强 RAG 在此基础上加入知识图谱上下文。为了使问答效果验证具有可复核性,本文将对照实验设计为同题双模式实验:每个问题分别使用普通项目 RAG 和图谱增强 RAG 回答,记录回答文本、资料来源、图谱依据、响应耗时和人工评价。评价人员依据项目原始实验笔记、审核资料和知识图谱页面判断回答是否准确、是否可追溯。

对照实验问题限定在论文演示项目范围内,避免引入系统外知识。问题分为四类:资料事实型、实验对象关系型、过程追溯型和综合总结型,每类 5 个,共 20 个问题。两种模式各回答 20 次后,可形成 40 条问答日志,并按 7.1 节指标分别统计。

| 问题类型 | 样本数 | 主要考察点 | 预期比较重点 |
| --- | ---: | --- | --- |
| 资料事实型 | 5 | 资料片段检索与来源展示 | 普通 RAG 与图谱增强 RAG 均应能回答 |
| 实验对象关系型 | 5 | 试剂、仪器、样本、结果关系 | 图谱增强 RAG 应更容易给出结构化依据 |

系统按附录 A 的 20 个问题执行同题双模式对照实验,共形成 40 条问答日志和 40 条人工评价记录。普通 RAG 模式(project_rag)和图谱增强 RAG 模式(kg_enhanced_rag)各 20 条,评价结果如表 7-2 和图 7-4 所示。

### 7.6 固定任务型智能辅助生成验证

系统当前支持实验总结、周报、阶段报告和实验过程图谱概览四类固定任务型智能辅助生成。实验总结任务针对单次或多次实验生成结构化整理结果,适合在完成一组相关实验后进行数据汇总和结果梳理;周报任务按周汇总实验进展,适合课题组在组会前快速生成实验进展报告;阶段报告任务面向较长时间范围的实验项目总结,适合项目阶段性汇报使用;图谱概览任务生成实验过程的知识图谱关系说明,帮助用户从整体上理解项目中实体和关系的分布情况。

验收数据中已有 8 条生成记录,覆盖全部四类任务类型,每条生成记录完整保存了任务类型、输入参数(日期范围等)、标题、正文内容、来源笔记 ID 列表、来源资料 ID 列表、来源图谱关系 ID 列表、处理状态和响应耗时等信息。从生成结果来看,固定任务型智能辅助生成能够有效利用已审核的实验笔记、资料文件和知识图谱关系生成结构化的文本输出,其内容可以直接作为科研汇报材料的基础草稿使用。

从功能角度看,固定任务生成不是简单的即时文本输出,而是与项目数据、来源依据和审计日志绑定。生成接口要求用户具备项目写入权限,只读成员可以查看生成历史但不能创建新记录。该设计能够满足科研记录场景下对生成内容可追溯和可人工复核的要求,也避免了开放式自主智能体在权限和责任边界上的风险。智能生成页面建议作为图 7-2 插入本节,展示任务类型选择、生成结果、来源数量和生成历史。

普通成员场景:具有写入权限的普通成员登录系统后,可以查看自己有权限访问的项目列表,进入项目后可以创建实验笔记、选择实验模板、填写结构化字段和实验正文、上传附件文件、保存草稿和提交审核。审核通过后可以在知识图谱页面查看笔记对应的实体和关系。普通成员还可以使用 AI 知识库进行问答,以及创建固定任务型智能生成记录,但无法评价问答结果。

审核人员场景:审核人员登录系统后,可以在审批中心查看待审核的实验笔记列表和待审核的资料文件,逐条进行审核操作并填写审核意见。审核人员还可以对 AI 问答结果进行评价,包括评分和判断准确性与可追溯性。

项目负责人场景:项目负责人可以查看项目内的实验笔记列表、资料库文件、知识图谱可视化页面、AI 问答记录和统计指标、智能生成历史以及项目审计日志。项目负责人还可以管理项目成员的角色和权限。

该流程对应真实课题组中的实验记录与审核、数据整理与知识管理、项目复盘与汇报材料准备等典型场景。

### 7.8 实验结果分析

综合测试结果、场景化验证和对照实验数据,系统已经实现了从实验笔记记录到知识图谱抽取、资料审核入库、图谱增强问答、问答评价、固定任务生成和审计追溯的完整闭环。与普通 ELN 系统相比,本文系统的差异主要体现在三点。

第一,系统将实验记录中的关键对象转化为知识图谱实体和关系,使实验知识可以被可视化和关联检索。第二,系统将项目级 RAG 与图谱上下文结合,使 AI 回答能够展示资料来源和结构化依据。第三,系统通过问答日志、评价记录、生成记录和审计日志,使 AI 辅助过程具备可复核路径。

从验收数据看,系统已形成 177 个知识图谱实体和 237 条知识图谱关系,说明演示项目中的项目、笔记、人员、附件、实验类型、试剂、仪器、样本和结果能够被组织为结构化知识。后端 26 个自动化测试全部通过,说明知识图谱、RAG、固定任务生成和权限边界具备基本回归测试保障。系统已形成 40 条 AI 问答日志和 40 条人工评价记录,普通 RAG 与图谱增强 RAG 的对照数据已支持量化比较。

系统在实验验证中也反映出一些需要改进的方面。当前图谱抽取方法以规则和结构化字段为主,对于包含复杂句式、专业术语缩写和隐含关系的自由文本实验记录,抽取覆盖率和准确性仍有提升空间,与基于深度学习的信息抽取方法相比在泛化能力上存在差距。普通 RAG 与图谱增强 RAG 的对照实验虽然完成了 20 个问题的双模式评价,但样本数量仍然有限,量化对比的统计显著性有待在更大规模的问答数据集上进一步验证。场景化验证采用了课题组典型角色流程进行功能走查,但尚未在真实的科研课题组环境中开展长期使用实验,缺少真实用户在实际工作条件下的满意度、任务完成效率和数据质量变化趋势等指标。上述不足不影响本文系统功能闭环验证和 RAG 对照实验的基本结论,但在将系统推广到更大规模的真实科研场景时,需要在图谱抽取能力、问答验证规模和使用环境适配性等方面进行进一步的完善和验证。

### 7.9 本章小结

本章围绕系统主问题建立了一套包含功能闭环指标、安全边界指标、知识图谱指标、问答评价指标和场景化验证指标在内的多维度评价体系,并按照该评价体系对系统进行了系统性的实验验证和分析。实验环境包括本地 Docker 服务、后端 26 个自动化测试、前端 TypeScript 类型检查和生产构建测试、运行时 API 冒烟测试以及浏览器关键路径验证。测试数据采用论文演示项目,包含 15 条已审核实验笔记、7 份入库资料、177 个图谱实体和 237 条图谱关系。

实验结果表明,系统能够完成实验笔记审核入图谱、资料入库、图谱增强问答、人工评价和审计追溯的完整功能闭环。20 题同题双模式对照实验显示,图谱增强 RAG 在准确率(100%)、可追溯率(100%)和平均评分(4.45/5)上均优于普通 RAG(85%、70%、3.90/5),验证了实验知识图谱上下文对问答质量的提升作用。固定任务型智能辅助生成的四类任务均能基于已审核笔记和图谱关系生成结构化的总结内容。对于最终定稿,仍需补充真实用户长期使用验证和更大规模的多项目数据测试。

## 第八章 总结与展望

### 8.1 工作总结

本文围绕"项目级权限约束下已审核实验记录的结构化知识组织与可追溯问答"这一核心问题,设计并实现了一套面向科研课题组的智能电子实验笔记系统。系统以项目为基本管理单元,涵盖用户管理、课题组管理、项目成员与角色分配、实验笔记全生命周期管理、附件资料分类管理、审核流程和审计日志等基础功能,为课题组提供了从实验记录创建到数据归档的完整管理流程。在这些基础功能之上,系统引入了实验知识图谱模块,采用结构化字段优先和规则抽取相结合的方式,实现了项目级实体关系抽取和可视化展示;引入了项目级 RAG 和图谱增强问答模块,采用资料检索与图谱上下文相结合的增强策略,实现了有来源依据的可追溯问答;引入了问答评价机制,支持对问答结果进行评分、准确性和可追溯性判定,为 RAG 效果比较提供了数据基础;引入了固定任务型智能辅助生成机制,实现了实验总结、周报、阶段报告和图谱概览四类结构化文书整理任务,为科研人员的周期性汇报和项目复盘提供了效率支持。通过项目级权限隔离、审核后入图谱、资料审核入库和 AI 操作日志记录,系统在演示项目中验证了实验记录从业务数据到结构化知识再到可追溯智能问答的完整闭环,证明了图谱增强 RAG 在实验记录管理场景中的有效性。

### 8.2 主要创新点总结

本文主要创新点包括以下三个方面。第一,提出审核约束下的项目级实验知识图谱构建机制。与现有知识图谱研究主要关注从文本中准确抽取实体关系不同,本文将知识图谱的更新时机与实验笔记的审核流程绑定,草稿和未审核内容不会进入图谱,只有审核通过的记录才能触发实体关系抽取。同时在实体、关系和抽取记录中保留项目编号和来源信息,使图谱知识具备项目边界和流程依据的双重约束,从根本上避免了未审核内容进入知识库对问答质量造成的潜在影响。第二,提出融合实验知识图谱上下文的可追溯 RAG 问答流程。在普通资料检索基础上引入项目内的实体关系上下文作为回答的结构化依据,并统一记录问答模式、资料来源、图谱依据、图谱命中数、响应耗时和人工评价结果,为 RAG 效果评估提供了可复核、可统计的数据基础。第三,设计面向实验记录整理的固定任务型智能辅助生成机制。将生成任务限定为实验总结、周报、阶段报告和图谱概览四类边界清晰的任务,记录生成结果所使用的来源笔记、来源资料和图谱关系依据,确保每一条生成结果都可以追溯到具体的实验记录和知识关系,不扩写为开放式自主智能体,兼顾了 AI 辅助效率和科研场景对结果可控性的要求。

### 8.3 不足分析

本文系统仍存在以下不足。第一,知识图谱抽取方法主要依赖结构化字段和关键词规则,对自由文本中隐含的实验关系、同义表达和长距离语义依赖识别能力有限。与基于深度学习的实体关系抽取模型相比,当前方法在抽取覆盖率和准确性上存在明显差距,尚不能替代面向开放文本的通用信息抽取方案。后续可以考虑引入预训练语言模型进行序列标注和关系分类,以提高复杂实验描述的图谱构建质量。

第二,当前演示数据虽然已覆盖 15 条实验笔记、7 份资料、177 个图谱实体和 237 条图谱关系,验证了系统的基本功能和闭环流程,但真实用户长期使用验证尚未开展。系统缺少真实课题组成员在日常使用中的满意度反馈、任务完成效率对比和数据质量变化趋势等指标,这些数据对于评估系统在实际科研环境中的适用性至关重要。

第三,系统 RAG 对照实验基于内置模拟问答服务完成,虽然确保了两种问答模式的比较口径一致,但真实环境下 Dify 外部服务的问答延迟、回答质量和并发处理能力仍有待在大规模使用场景中验证。模拟服务无法完全替代真实外部服务在不同网络条件和服务负载下的表现。

第四,场景化验证采用了典型角色流程测试,覆盖了管理员、项目负责人、审核人员、普通成员和只读成员等角色,但尚未扩展为真实课题组连续数周或数月的长期使用实验。长期使用中可能出现的性能问题、用户习惯适应和数据积累效果等仍需进一步观察。

第五,固定任务型智能辅助生成结果仍需要人工复核,系统尚未建立自动化的生成质量评价机制。虽然系统保存了生成内容的来源笔记、资料和图谱关系,但这些依据的完整性验证仍然依赖人工判断。

### 8.4 未来展望

后续工作可以从以下方面展开。第一,引入基于预训练语言模型的实体关系抽取方法,与当前基于规则和结构化字段的方法进行对比实验,评估不同方法在准确率、召回率和 F1 值上的差异,为不同类型实验笔记选择最合适的抽取策略。

第二,配置完整的 Dify 外部问答服务,在真实网络环境和服务负载下重新执行 20 题同题双模式对照实验,验证模拟环境下的结论是否在真实环境中保持一致,并在更大规模的实验笔记和资料数据集上测试图谱增强 RAG 的稳定性和泛化能力。

第三,完善多模态资料处理能力,将实验图片、仪器输出数据、表格数据和原始数据文件纳入统一的知识管理范围,扩展知识图谱的实体类型和关系定义,覆盖更多类型的实验对象和实验操作。

第四,引入自动化的生成质量评价机制,通过预设的评价指标和比对规则减少对人工复核的依赖,使固定任务型智能辅助生成结果更适合大规模科研项目管理场景。

第五,将系统部署到真实的课题组使用环境中,收集多个项目的长期使用数据,包括用户操作日志、问答反馈、生成任务使用频率和满意度评价,从实际使用效果的角度验证系统的可用性和有效性。
