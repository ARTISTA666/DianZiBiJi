## 2. 优先修改的数据与论证问题

### 01｜项目三的研究场景前后互斥【高优先，确定错误】

### 03｜图 6-4 的“证据覆盖率”其实只是非空命中率【高优先，指标定义错误】

**位置**：6.6.4、图 6-4（B0593；图见印刷第 64 页）。

原文称左轴为“证据覆盖率”，并称默认阈值“有效保留了部分低质关系过滤能力”。但绘图脚本 `scripts/render/generate_kg_sensitivity_chart.py:48` 的计算是：

`返回至少 1 条关系的问题数 / 20`。

因此 95% 只表示 19 道题返回了关系，**不表示 19 道题获得了正确或完整的答案证据**。它也不同于前文 18 个事实题上的答案要点覆盖统计。图中英文 Graph coverage 同样容易造成误解。

**修改**：图轴、题注、正文统一为“图谱非空命中率（20 题）”；把质量论断改成“阈值提高减少了低得分候选，是否改善证据相关性与完整性尚未验证”。仅凭分数低不能证明关系质量低。

### 04｜序列化消融的失败原因解释与原始语料不符【高优先，影响核心论证】

**位置**：6.6.5（B0602）“三元组文本缺少的结果或仪器信息”。

**建议替换**：“臂 B 在 Q10、Q17 上未取得完整答案；相关仪器或结果信息在三元组文本语料中存在，但未被该题的检索上下文完整选中。该失败不能单独归因于三元组表示的信息缺失。” Q17 还须保留论文已披露的跨题指代问题。

### 06｜CD63 与 anti-CD63 抗体不能作为同义词归并【高优先，概念错误】

**修改**：“差异涉及目标知识点、检测抗体与检测结果之间的领域关系映射，不能仅用同名同类型匹配处理。” 人工 3/15 可保留为人工主题关联口径，但须说明映射依据；不能作为同义实体合并的金标准。也不能由记录出现抗体直接推出目标知识点已得到有效实验验证。

### 07｜Rust 配对结果将两个指标的改善题数混排【中优先，数字正确但标签缺失】

### 10｜改写的生成摘要被放进“真实生成正文”引号【中优先，逐字引用准确性】

**位置**：5.4（B0447、B0453、B0454），周报与阶段报告摘录。

## 3. 实现与论文规格的偏差

以下依据当前源码静态核对，不把当前缺陷反推成历史批次数字造假；若论文描述的是不同历史实现，应补充对应 revision。

### 11｜退回率统计漏掉当前 API 产生的正常退回动作【高优先，当前代码缺陷】

表 4-8（B0403）定义近 10 条审批的退回比例。`backend/src/api/notes.rs:759` 写入 `action="returned"`，经 insert_approval 原样进入审批表；`backend/src/project_alert.rs:88` 却只计 `action == "return"`。

因此通过当前 API 正常退回的记录不会进入退回分子，即使真实发生退回也可能显示 0。历史复算 0.1 可能来自不同动作口径，现有材料不足以说明其来源，**不能仅凭历史 SQL 数字相符证明当前端到端指标正确**。

处理：统一动作枚举，并用正常 API 完成提交—退回—评估后验证。在修复验证前，论文只能保留“历史快照复算相符”，收窄“已完整验证当前指标”的表述。本轮未改代码或进行运行时复测。

### 12｜将候选条数增至 30 不能保证统计证据完整【中高优先，保证不成立】

B0470 原句：“上限自动扩展到 30 条，保证统计类问题证据完整”。当前 `backend/src/api/rag/mod.rs:698` 为配置上限与 30 取大；`rag/graph.rs:135–146` 有候选硬过滤和阈值，`:256–270` 有额度选择，`:16,296` 还有 6000 字符预算。

**建议替换**：“集合意图将候选上限提高至至少 30 条，以缓解固定 top-k 截断；仍受过滤、条数和字符预算限制，不能保证全量统计完整性。” 与第六章“仍须另行验证”统一。

### 13｜“Unicode NFKC”不是当前实际归一化算法【中优先，算法规格错误】

B0318 写 NFKC；`backend/src/knowledge_graph.rs:950–988` 实际手工转换全角 ASCII 和全角空格，再做小写、标点、空白清理及同义词表归并，未执行完整 NFKC。圈号数字、兼容连字等不具有完整 NFKC 的转换行为。

**修改**：按实际步骤描述，注明同义词表及版本；或实现真正 NFKC 后另行验证，不要仅凭全角字母测试称已实现 NFKC。

### 14｜图谱评分公式没有完整描述候选选择机制【中优先，可复现性】

式（4-5）及说明（B0361—B0363）强调关系类型加分，但当前 `rag/graph.rs:135–143` 在出现类型提示时先排除其他类型，有焦点实体时还排除无关实体关系；这些是硬过滤，不是少拿几分。`:182–194` 使用 confidence 打破同分，后续还做来源/关系/角色分组均衡。

此外，`src_type(src(r))` 易被理解为源节点类型；实现 `:483` 读取的是关系自身的 source_type。应改记号为关系的来源类型并定义清楚。

**修改**：公式前补候选集定义，公式后补阈值、同分、分组与预算处理。保留“置信度不进入线性相关性分值”，不要推成“置信度绝不影响排序”。历史固定 20 题排序不变可以作为批次观察保留。

### 15｜“蓝图停滞天数”度量的是实体更新时间，不一定是新实证时间【中优先，指标语义偏差】

B0339、表 4-8 把它解释为最近实证匹配或覆盖距今天数。`backend/src/kg_blueprint.rs:547` 和 `project_alert.rs:101` 使用 `kg_entities.updated_at`；`knowledge_graph.rs:499–505` 对已有实体重抽 upsert 也写 now()。原样重建旧笔记图谱即可刷新该时间，未必出现新实验或新增覆盖；无匹配实体时还以 0 处理。

**修改**：现版本可如实称“已匹配实体距最近图谱更新的天数”，说明重建与无匹配情形。若要衡量科研停滞，应另记新增实证或覆盖事件时间，不能只改名称后继续推断真实科研进度。

### 16｜六个 MCP 模板清单前后不一致【中优先，接口事实】

B0380 列 `protocol_refinement/troubleshooting_guide/kg_overview`，附录 C（B0785）列 `graph_overview/literature_review/anomaly_detection`；前三个总结类一致。`backend/src/api/mcp.rs:713–720` 支持附录清单。

**修改**：据运行版本统一 4.8.1；区分“暴露六个模板”与“论文实际验证四类固定任务”，避免未验证范围被清单扩张。

### 17｜数据库 33 张表与当前完整建表定义不符【中优先，统计口径】

B0280 写“共 33 张表”。对当前生产建表语句按名称去重，`backend/sql/0001_initial.sql` 有 35 张，`backend/src/db.rs` 有 17 张运行时 CREATE TABLE（其中部分重复），并集为 **43 张**；排除 `alembic_version/rust_schema_versions` 仍为 **41 张**。这是静态定义统计，不是线上实例实查。

**修改**：冻结统计 revision、明确业务表/运行时表/版本表是否计入，再同步正文和附录。或取消无必要的总表数，改写模块结构。表 4-3 的 `alert_thresholds` 也应对齐实际 `project_alert_thresholds`。

### 18｜退回状态与评价授权规则存在文字—代码错位【中优先】

- B0275、B0462 把笔记退回状态写为 `REJECTED`；笔记枚举及 API 是 `RETURNED`。`REJECTED` 属于资料状态。应同步检查图 5-6 和全文。
- 表 4-1（B0264）称仅有 `can_review` 或 project_reviewers 授权的审核员可提交问答评价，但 `backend/src/permissions.rs:218` 起实际要求 `can_evaluate` 或 `can_manage`（系统管理员另行放行）。审核授权不自动推出评价授权。
- 同表将 owner 身份、OWNER 角色和 can_manage 混作等价授权，式（4-1）却不含 owner 的审核分支；当前审核函数也未仅凭 owner 身份放行。如果依赖创建时默认授予能力位，应明确这种配置前提。

**修改**：按真实权限函数列出必要条件，区别身份、默认角色配置和独立能力位。式（4-1）应补充归档否决、独立审核授权，或明示只是简化模型；避免“四项/五项能力位”交替。

## 6. 收口建议

先修项目身份、基因行数、图轴定义、配对指标标签和提示版本；再修消融失败解释、建议归档及抗原/抗体映射；随后处理实现规格偏差和绝对化措辞。以上大部分可依据现有证据完成，不需要重跑生成模型。

当前退回率动作不匹配需要代码修复及端到端验证；停滞指标若继续承担“科研进度”的语义，也需要改变事件记录口径或明确收窄主张。这两类不能靠润色文字假装已完成实现验证。

修订后应对新 Word 做全文差异审计，再复查本清单；没有不同的内容哈希，不能将文件改名视为问题已关闭。任何历史冻结工件都不应为迎合论文表述而回改。
