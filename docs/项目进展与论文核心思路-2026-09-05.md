## 二、论文核心思路

### 2.1 中心问题与三个子问题

**中心问题：让 AI 进入科研记录流程，而不破坏可复现性与可追溯性。** 展开为三个子问题，每个子问题对应系统的一个核心机制和一组实验验证：

| 子问题 | 系统机制 | 验证 |
| --- | --- | --- |
| 一、AI 产生的记录回不到原始数据（生成内容无法核验） | **审核门禁流水线**：AI 产出与外部资料必须经审核状态流转才能入库、入图谱、进检索 | 权限边界测试、提审-审批状态机、审计留痕 |
| 二、关系型问题没有证据来源（"谁用了什么试剂"答不出出处） | **可审计证据链 + 图谱增强 RAG**：式(5-3) 证据评分融合图谱关系与向量/词法检索，回答带 [S]/[G] 编号引用并做引用校验 | 实验 4、实验 5、式(5-3) 系数消融 |
| 三、AI 生成脱离科研用户的审核权限（自主生成不可控） | **安全运行时**：仅开放固定任务型生成，带确认队列、幂等防重放与全程审计 | 3 项安全性质测试、运行时证据 |

### 2.2 三个创新点（与已有路线的差别）

1. **审核门禁流水线**：首次把业务审核状态确立为 AI 可用知识的前置条件——GraphRAG/LightRAG 等路线以通用语料为对象、无审核语义，openBIS 等 ELN 具备权限但无 AI 知识门禁（对比见论文表 1-1）。
2. **可审计证据链 + 图谱增强 RAG**：学术立场是"可追溯性优先于检索覆盖率"——回答必须能逐条回指原始记录，宁可声明"无法确认"（系统真实行为：证据不足时明示）。
3. **安全运行时**：用可枚举的机制约束（固定任务类型 + 确认队列 + 幂等键）替代概率性提示约束，并有集成测试证明。

### 2.3 关键实验结果（两批独立证据收敛）

| 实验 | 结果 |
| --- | --- |
| 实验 4（RAG 质量对照，legacy 批次，20 题双模式） | 图谱增强将问题案例 4→14 修复，McNemar p=0.0020，修复后 F1=100% |
| 实验 5（五方法扩展，180 案例=单项目 12×5×3） | 36 个配对案例中改善 27 例、持平 9 例、恶化 0 例 |
| 图谱抽取金标准（53 条关系逐条核对） | Precision 98.11%、Recall 100%、F1 99.05%（唯一误抽取案例已披露） |
| 式(5-3) 系数消融（2026-09-04，离线无 LLM） | 172 条真实候选池、7 个变体档位重打分：幸存集完全一致、Kendall τ≥0.9752、引用位移≤0.26；角色命中为未触发的休眠参数 |
| Rust 交付系统 20 题成对重跑（2026-09-04，run#24） | micro-F1 0.9821 vs 0.9286、exact 0.95 vs 0.85、3 改善 0 恶化；严格引用审计 40/40 零违规 |

口径纪律：实验 4 与 Rust 重跑的题集和语料均不同，论文中只作"独立题集复现同一方向"的表述，不并列数字。

### 2.4 诚实性边界（论文限定语体系）

所有强结论均携带口径限定，未做的人工评价如实写明未做：legacy 批次与交付系统的口径分离、反算权重标 `INFERRED` 不作为系统配置、`paper_ready=false` 边界、**人工盲评尚未签核**、封闭单项目验证不支持跨项目泛化。证据分级与限定语在论文 1.5/5.1/8.3 集中呈现。

### 3.3 全流程演示走查（2026-09-05，已录屏）

当日以两个账号（项目负责人 + 普通成员）完整走查"登录 → 记录 → 提交审核 → 审批通过 → 图谱 → 引用问答 → 审计"闭环，全程录屏存档。审计日志新增 11 条记录完整覆盖双账号链路（login / query_local_rag / submit_ai_query_feedback / submit_note / auto_extract_note_kg / approve_note / logout），其中**审批通过自动触发图谱抽取**。走查中权限边界正确工作：非笔记作者提交草稿被系统拒绝。

### 3.4 走查中发现并修复的真实缺陷

**缺陷**：绕过创建/编辑路径产生的无版本快照草稿（如脚本直接灌库的数据）提交审核后，进入"SUBMITTED 但无版本"死状态——审批页报"未找到笔记版本"，通过/退回永久不可用（approve/void 依赖 current_version_id）。

**修复**（commit `7a4ffba`，2026-09-05）：提审事务内发现无版本时自动补建版本快照并绑定，保证不变式"进入审批队列的笔记必有版本可审"；附回归测试。验证：cargo fmt / clippy(-D warnings) 全绿，全量数据库集成测试 266 通过 0 失败。

## 五、工作方式（研发协作机制）

项目采用"研究者负责制 + 多智能体工程流水线"：研究问题定义、方向决策、实验取舍与每轮质量验收由研究者负责；系统实现、实验执行、论文成文与评审由并线的多智能体协作完成（证据线负责机制性修改/测试/实验，文字线负责纯语言修改），以单写者窗口、修改前基线快照、逐轮 diff 审计、预注册冻结与提交前缀纪律保证全程可审计。协作约定见 `AGENTS.md`，过程档案见 `reviews/`（round-01~11）。
