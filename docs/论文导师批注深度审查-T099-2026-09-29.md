## 三、独立发现的交付与证据问题

1. **图号和可见性（高优先级）**：第四章依次出现 4-1、4-2、4-3、4-4、4-6、4-6、4-7、4-10、4-9、4-10、4-11；“图 4-6”用于两个不同图（Word XML 段落 P474/P552），“图 4-10”也用于两个不同图（P594/P626），图 4-5/4-8 缺失。第五章还先出现图 5-5、5-6、5-7，之后回到 5-3、5-4。图题及交叉引用因此含糊。两张总流程图在当前包中有实际 PNG，而当前 LibreOffice PDF 的对应图题下未见图面；这是已证实的 PDF 可见性问题，不应误报为“图片未嵌入”，WPS/Word 显示仍待实测。
2. **摘要 85.0% 的证据语义（高优先级）**：中英文摘要称 85.0% 回答有“可核对/verifiable”来源编号；表 6-6 对应列为“包含任一证据标记”。[RAG 证据索引](experiments/rag-paper-evidence-index-v1.md) 第 37 行明确，历史 85.0%=17/20 的宽松 `"[G"` 子串口径，含非法范围标记；按严格有效引用规则只有 15/20=75.0%，且明确要求论文不得把 85.0% 写成有效引用率。摘要与表格须分别标注宽松/严格口径，或统一采用严格值。
3. **表 6-7 混用分母（高优先级）**：表题称“项目一 20 题”，却并列裸 LLM 2/20、普通 RAG 4/20、KG 8/14、SQL 11/14 的完成率；图/表把不同题集上的数值当作可直接比较。[基线记录](experiments/rag-ablation-baseline-2026-08-26.md) 第 100—117 行给出同 14 题与同 20 题各自的口径，二者应分表或明确逐列分母。相关耗时也分别来自 20 题和 14 题，须同口径核对。
4. **实验运行时归属（高优先级）**：6.1 节称除 Rust 迁移前主对照实验外“其余实验均在当前交付系统上运行”；但 6.5 节明确扩展五法对照是“原型开发期”内部材料，运行版本与工作树状态未绑定。摘要的 4→14/20 亦未提示历史 Python 批次，易被读作交付 Rust 系统实测。应按实验逐一标明运行时与证据等级，不能统一归为当前系统。
5. **Token 指标误名（中优先级）**：表 6-9 和图 6-7 标为“输出 Token”，其 2191、2071、4187、1391 实际是四份 `docs/experiments/agent-*-final.json` 的 `total_tokens`；真正 `completion_tokens` 依次为 1194、1074、1468、490。须统一改为“总 Token”或替换数值。
