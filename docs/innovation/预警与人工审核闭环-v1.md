# 创新点四 · 预警与人工审核闭环机制 v1

> 来源：2026-09-06 创新点讨论确立的创新点四——「不是每步都让导师审核，而是
> **AI 自主推进 + 阈值触发报警 + 导师自主干预**」。每一步都审与"减轻导师负担"的目标矛盾；
> 导师的每个动作（确认/调阈）都构成对 AI 判断的反馈，驱动阈值与口径逐步收敛到该实验室的风格。
> 后端：`backend/src/project_alert.rs` + `backend/src/api/project_alert.rs`（tag `innov4-alert-v1`）；
> 前端：`frontend/src/components/project-alerts.tsx`（项目导航「预警」页签，reviewer 及以上可见）。

## 一、机制设计（三段闭环）

```
指标计算（AI 自主）──越界──▶ 报警收件箱（阈值触发）──人工──▶ 导师干预（确认/调阈）
        ▲                                                        │
        └────────────── 下一次评估沿用新阈值 ◀── 审计留痕 ────────┘
```

1. **指标计算**：`evaluate` 端点按四维指标实时计算当前值，全部由系统内既有数据推导，无人工输入；
2. **报警触发**：值 ≥ critical → critical 级；≥ warn → warn 级；同一指标同时最多一条 open 告警
   （部分唯一索引幂等去重，重复评估只刷新值与级别）；指标回落正常区间后 open 告警**自动转 resolved**；
3. **导师干预**：确认（acknowledge，可带备注，open→acknowledged）与调阈（upsert threshold，
   仅 manage 权限）都写审计日志——闭环的"人工动作"侧全部可追溯。

## 二、四维指标（v1）

| 指标 | 语义 | 数据来源 | 缺省 warn / critical |
| --- | --- | --- | --- |
| `review_stall_hours` | 最老待审笔记等待时长（小时）——审批流水线是否堵转 | `experiment_notes`(SUBMITTED).updated_at | 72 / 168 |
| `return_rate` | 近 10 条审批中退回占比——提交质量信号 | `note_approvals`（action=return） | 0.3 / 0.5 |
| `blueprint_stagnant_days` | 知识蓝图最近实证距今天数——项目是否停滞 | `kg_blueprint_nodes` ⨝ `kg_entities` | 14 / 30 |
| `progress_deviation` | 蓝图待实证知识点占比——实际进展 vs 预期进展的偏差率 | 同上（覆盖度取反） | 0.7 / 0.9 |

指标 3/4 直接复用创新点一的知识蓝图：**蓝图定义"预期"，实证覆盖定义"实际"**，
偏差率即导师面谈所说的"实际进展与预期进展的偏差率"。

## 三、阈值体系

- 白名单四指标（`ALERT_METRICS`），非法 metric 400 拒绝；warn ≤ critical 服务端校验；
- 缺省阈值内置（上表），导师未配置时即开箱可用；配置后以库内为准，可逐指标 `enabled=false` 停用；
- 调整权限 = `can_manage_project`（super_admin / 项目负责人 / can_manage 成员），
  每次调整产生 `alert_threshold_upsert` 审计事件；
- 可调性即收敛机制：实验室按自身风格收紧/放宽阈值，长期形成该导师的预警口径
  （与讨论中"阈值可调、调整权限开放给导师"完全对应）。

## 四、权限与审计

| 操作 | 权限 | 审计事件 |
| --- | --- | --- |
| 评估（含自动 resolved） | 项目读权限 | `alerts_evaluate`（含各指标值与 resolved 数） |
| 查看收件箱/阈值 | 项目读权限 | — |
| 确认告警 | manage | `alert_acknowledge`（含备注） |
| 调整阈值 | manage | `alert_threshold_upsert` |

## 五、验证

- Rust 集成测试 2 项：停滞告警全生命周期（提交→critical→审批通过→自动 resolved→
  历史不可再确认）与确认/权限边界（成员 403、非法指标与倒挂阈值 400、备注落库）；
- 迁移 0016（SQLite/PostgreSQL）+ 运行时 ensure（schema v6）双路径；
- 前端 lint/typecheck/build 全绿；演示路径：审批页签提交笔记 → 预警页「立即评估」→
  critical 报警 → 导师确认并调阈 → 审批通过后再评估 → 自动 resolved。

## 六、诚实性边界

- v1 指标由**显式触发评估**计算（导师点「立即评估」或后续接入定时任务），不是后台常驻守护进程——
  这保证每次报警都可归因到一次可审计的评估动作；
- 退回率窗口固定 10 条；导师"确认后参数自动调整、思维链比例收敛"的完整自学习在 P2 智能体增量中
  落地（确认动作现在已留痕，为学习信号提供数据）。
