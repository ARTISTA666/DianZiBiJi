# 预警与人工审核闭环机制 v2

T139根据当前Rust实现校正指标含义，取代[v1](预警与人工审核闭环-v1.md)的现行说明。v1保留其历史描述和验证记录；本协议不修改历史运行快照。

评估端点从数据库计算四项指标，与项目阈值比较，并记录审计事件。评估由显式请求触发；当前实现不包含常驻监控或由模型自主判断、学习阈值的过程。管理者确认告警、填写备注或调整阈值，下次评估使用保存的配置。

| API指标键 | 当前显示名称及计算含义 | 默认warn / critical |
| --- | --- | --- |
| `review_stall_hours` | 审批停滞：最早SUBMITTED笔记的最近更新时间距今小时数 | 72 / 168 |
| `return_rate` | 退回率：近10次批准或退回操作中的退回占比 | 0.3 / 0.5 |
| `blueprint_stagnant_days` | 匹配实体最近更新间隔：与有效计划点按项目、实体类型及规范名匹配的实体中，最近一次`updated_at`距今天数 | 14 / 30 |
| `progress_deviation` | 进展偏差：有效计划点中未匹配图谱实体的比例 | 0.7 / 0.9 |

对应集合为空时取0。第三项的历史API键保持兼容，但不表示“多久没有新增计划覆盖”：重抽笔记会刷新实体更新时间，即使覆盖集合不变，也会重新计时；完全无匹配实体时取0。第四项表达当前未匹配比例，不直接度量实验目标完成质量或项目整体进度。

值达到critical阈值时产生严重告警，达到warn阈值时产生警告；已禁用指标为正常。每项目每指标最多保留一条open告警，重复评估刷新其读数与明细；读数恢复正常时，下次评估将open告警转为resolved。已确认的历史告警保持acknowledged状态；再次越界可以产生新的open告警。

查看和评估需要项目读权限；确认和调阈值需要项目管理权限。指标键限定白名单，阈值须非负且warn不高于critical，占比指标限定在0至1之间。计算、处置和阈值调整均可通过审计记录回查。

实现入口：[指标计算](../../backend/src/project_alert.rs)、[API与集成测试](../../backend/src/api/project_alert.rs)、[前端提示](../../frontend/src/components/project-alerts.tsx)。T139新增回归测试核验无匹配取0、重抽后间隔复位且未匹配比例不变；执行结果见[整改记录](../论文审核问题整改-T139-2026-10-11.md)。
