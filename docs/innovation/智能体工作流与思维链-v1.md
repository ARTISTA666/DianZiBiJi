# 创新点二 · 智能体工作流与思维链机制 v1

> 来源：2026-09-06 创新点讨论确立的创新点二——定位不是"智能笔记"，而是**"AI 导师助手"**：
> 主动引导、主动给下一步建议、带思维链、能自动调用后端 MCP 工具；
> "工作流是自己搭的，思维链是自己设计的，调用方式与调用比例由自己设定"。
> 本文档覆盖两部分：**主动建议**（v1 新增）与**工作流/思维链展示**（v1 新增）。
> 后端：`backend/src/api/agent_suggestion.rs`；前端：`ai/page.tsx` 建议卡 + `AgentAssistant.tsx` 思维链时间线。
> 里程碑 tag：`innov2-agent-v1`。

## 一、与论文已有三创新的关系

系统本就有自研 Agent 安全运行时（论文创新三：`agent_runtime.rs`，计划审批模式、
fast/deep 双档预算、10 个 MCP 工具、高风险人工批准、幂等防重放、步数硬预算）。
本增量在其上补齐**"AI 导师"行为面**：

| 讨论原话 | 落地机制 |
| --- | --- |
| "主动引导、主动给下一步建议" | 主动建议端点：从知识蓝图未覆盖知识点推导"下一步做什么" |
| "他有思维链的……帮你探索、指导下一步" | 思维链时间线：plan.preview → tool.started → confirmation → tool.completed 实时渲染 |
| "他会主动调后面的 MCP" | 复用 10 工具注册表，调用全程经安全运行时（审计+幂等） |
| "调用方式与调用比例由你设定" | 双档预算（12/32 步、6/16 次模型调用）与工具风险分级即"比例"的自定义 |

## 二、主动建议机制（数据流）

```
知识蓝图未覆盖知识点（创新点一）
        │  entity_type/label/description/priority/source_kind
        ▼
LLM 归纳（系统提示词约束：严格 JSON、≤3 条、related_labels 必须逐字来自清单）
        │  失败/未配置 AI → 规则兜底（按 priority 排序 + 类型→动作映射）
        ▼
防编造校验（related_labels 过滤：不在未覆盖清单的标签丢弃）
        ▼
"下一步建议"卡（AI 页）：总览 + ≤3 条建议（标题/理由/关联知识点）+ 执行提示
```

- **三种模式如实留痕**：`empty`（无蓝图）/ `llm` / `rule_based`，message 字段说明回落原因；
- **审计**：每次建议产生 `agent_next_step_suggestion` 事件（mode、覆盖率、待覆盖数）；
- **与蓝图联动即闭环**：解析计划书 → 建议出现；审核通过同名笔记 → 覆盖度上升 → 建议消失。

## 三、思维链时间线（工作流可见性）

AgentAssistant 全局助手面板新增可折叠「思维链（N 步）」时间线，由 SSE 事件驱动：

| SSE 事件 | 时间线条目 | 状态点 |
| --- | --- | --- |
| `plan.preview` | "生成研究计划" + 计划文本摘要（240 字） | 绿（done） |
| `tool.started` | "调用 <工具名>" + 参数摘要 | 蓝（running，脉动动画） |
| `confirmation.required` | "高风险操作 <工具名> 等待确认" | 琥珀（waiting） |
| `tool.completed` | 就近的 running 条目 → done | 绿 |
| `turn.completed/cancelled` | 收尾：全部 running → done | — |

设计约束：思维链只展示**已发生在服务端的真实动作**（计划、工具调用、确认等待），
不虚构中间推理文本——与系统的可审计立场一致；参数摘要沿用后端的脱敏
`arguments_summary`，不泄露原始参数。

## 四、验证

- 后端 2 项集成测试：无蓝图 empty 模式；解析蓝图→规则建议覆盖未覆盖知识点→
  审核通过同名笔记后建议清空（覆盖率 100%）；
- 前端 lint/typecheck/build 全绿；273 项 Rust 测试（CI 模式）全绿；
- 演示路径：图谱页解析计划书 → AI 页出现"下一步建议"卡 → 按建议做实验、审批通过 →
  重新打开 AI 页建议消失 → 全局助手发消息 → 观察思维链时间线随工具调用推进。

## 五、诚实性边界

- 思维链是**动作序列**（plan/tools/confirmation）而非 LLM 内部逐 token 推理——
  展示粒度由服务端事件决定，这也符合"可审计优先于透明度"的学术立场；
- 主动建议的输入仅蓝图缺口（v1），学生画像因素（创新点五）为 v2 预留输入；
- rule_based 模式的建议质量有限（按优先级排序的固定动作提示），但其存在使系统
  在无 AI 配置下仍可演示完整闭环，且两种模式的边界在响应中明示。
