# 创新点五 · GraphRAG 融入学生画像（设计文档，原型级）

> 来源：2026-09-06 创新点讨论的"可选加强"——在 graph 一跳/两跳 + 向量相似度检索中，
> 引入学生技能点、完成强度、实验速度、笔记更新速度、提交质量等因素，
> 用于个性化指引和任务分配。导师明确："想做算法，可以在 graph RAG 上加一点点"。
> **本文档是设计原型（导师口径：不必全部实现，有思想+原型 demo 即可）**，
> 不含实现代码；落地位置预留为 `backend/src/rag/graph.rs` 的重打分阶段。

## 一、机制设计

### 1.1 学生画像特征向量（全部由系统既有数据推导）

| 特征 | 定义 | 数据来源 |
| --- | --- | --- |
| `completion_speed` | 完成强度：近 30 天 APPROVED 笔记数 / 课题组同角色中位数 | `experiment_notes` |
| `quality_score` | 提交质量：1 − 近 10 条审批退回率 | `note_approvals` |
| `note_activity` | 笔记更新速度：近 7 天笔记 updated_at 次数 | `experiment_notes` |
| `skill_breadth` | 技能宽度：该学生笔记中出现过的不重复实体类型数 | `kg_relations`(created_by 溯源) |
| `blueprint_alignment` | 画像对齐度：该学生笔记覆盖的蓝图知识点 / 全部蓝图知识点 | 蓝图 ⨝ 实证图谱 |

### 1.2 融合位置：检索重打分，不改召回

现有混合检索（pgvector 余弦 + BM25 融合）保持不变，画像作为**第三路信号**
在式(5-3) 重打分阶段叠加（与既有图谱关系分同型）：

```
score_final = score_hybrid × (1 + λ₁·graph_score + λ₂·profile_score)
profile_score = Σ wᵢ·fᵢ(学生特征, 候选知识点的类型/难度)
```

- `λ₂` 与各 `wᵢ` 为**作者定义的参数**（经验值起步，文献引用作为起点；
  人工反馈逐轮调整——与预警闭环的"导师动作触发参数收敛"同构）；
- 指引应用一：同一问题对不同学生返回不同的"下一步"排序（新手先补基础试剂/样本类知识点，
  熟手直接推进 result 类）；
- 指引应用二（任务分配）：组间/项目间调配时按 `completion_speed × quality_score` 排序推荐承接人。

### 1.3 与三个已落地创新点的衔接

- 蓝图（创新点一）提供"预期"，画像提供"这个人实际到哪了"——两者的差是个性化指引的输入；
- 预警闭环（创新点四）的确认/调阈动作即画像参数的人工反馈信号；
- 消融实验口径（答辩第一问的正面回答）：`profile_score` 有/无两档对比检索质量
  （复用 RAG 实验区 6 模式对比协议），入消融表。

## 二、原型演示路径（不做后端实现时的替代演示）

以演示项目五人组（陈薇/李娜/赵鹏/孙佳/王芳）的真实审计数据离线计算画像向量，
输出对比表：同一检索问题在"无画像/有画像"两档下的 Top-5 差异与解释，
作为论文 5.x 节插图与答辩 demo。

## 三、诚实性边界

- 特征全部来自系统真实数据推导，不引入外部标注；
- 检索主链路（召回）不改动，画像只作用于重排序，风险可控、可消融、可回滚；
- 冷启动：新学生无审批记录时画像分数取课题组中位数（缺省值在论文中明示）。
