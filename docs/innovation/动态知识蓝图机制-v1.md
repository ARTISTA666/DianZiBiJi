# 创新点一 · 动态知识蓝图机制 v1

> status: current
> owner: 证据线

> 来源：2026-09-06 创新点讨论确立的创新点一——「动态知识图谱的构建与持续更新」。
> 本文是该创新的**机制定义文档**：计划态蓝图的产生、与实证图谱的对齐、来源冲突消解与完成度度量。
> 后端实现：`backend/src/kg_blueprint.rs` + `backend/src/api/kg_blueprint.rs`（蓝图 tag 见 git log）；
> 前端实现：`frontend/src/components/kg-blueprint.tsx`（图谱页「知识蓝图」页签）。

## 一、要解决的问题

传统知识图谱（含本系统 v0 的实证图谱）都是"做了什么记什么"：只有碎片化的已完成记录，
**没有覆盖全部知识点的计划框架，因此无法起到导引作用**——图谱回答不了"下一步该做什么"。
本机制引入**计划态蓝图**：项目计划书/大纲解析出覆盖全域的知识节点（计划态），
随实验记录（实证态）逐步覆盖，二者之差即"下一步指引"。

## 二、机制设计（四条核心规则）

### 规则 1：双态图谱（计划 vs 实证）
- **计划态**：`kg_blueprint_nodes/edges`，来源为计划书解析、组会纪要修正或人工调整；
- **实证态**：既有 `kg_entities/relations`，仅由审核通过的实验笔记抽取产生（审核门禁不变）；
- **覆盖判定**：按 `(实体类型, 规范名)` 精确匹配——蓝图节点在实证图谱中存在同名同型实体即"已覆盖"。
  规范名复用实证图谱的同义词消歧与全角/标点归一化（`normalize_entity_label`），
  使"qPCR"与"实时荧光定量聚合酶链反应"视为同一知识点。

### 规则 2：来源优先级冲突消解（"按谁说的做"）
同一知识点的多次定义冲突时，按来源优先级覆盖，**数值越小优先级越高**：

| 来源 | 优先级 | 语义 |
| --- | --- | --- |
| 组会纪要（meeting_note） | 10 | 导师意见最高——"开会改了就要按会议的来" |
| 项目计划书（plan_document） | 50 | 初始蓝图基准 |
| 人工调整（manual，预留） | 100 | 学生自主调整，不得覆盖前两者 |

实现：活跃节点按 `(项目, 类型, 规范名)` 唯一；新来源优先级更小时**就地覆盖**其描述、
来源与优先级并留痕（不删除历史解析记录），否则保持现状。每次解析在 `kg_blueprint_documents`
留痕（标题/来源/解析模式/增删计数/消息），全程可审计。

### 规则 3：动态更新（边做边改，图谱越来越准）
- 上传/粘贴新的计划文本或组会纪要 → 重新解析 → 增量合并进蓝图（新增/覆盖/保持三种结果）；
- AI 解析失败或未配置时自动回落规则抽取（复用实证图谱的术语识别器），模式如实记录；
- 导师/负责人可手动作废（retire）计划节点或关系，作废不参与覆盖度计算。

### 规则 4：完成度度量与导引
- 节点级：`evidence.entity_count > 0` 即已覆盖，记录最近实证时间；
- 项目级：`completion = 已覆盖计划节点数 / 总计划节点数`；
- **导引输出**：未覆盖节点清单 = "下一步指引"，同时驱动可视化（虚线空心节点）
  与后续智能体建议（P2）及预警指标（P1-b 的进展偏差率分母）。

## 三、与既有创新的衔接

- **审核门禁**：蓝图只定义"计划什么"，实证覆盖永远来自审核通过的记录——AI 可用知识的前置门禁语义不变；
- **可视化语义映射**（创新点三）：水波通道按预定路线从"证据新鲜度"升级为"计划完成度"
  （蓝图视图中已覆盖=满波、待覆盖=空心）；远近通道待蓝图关系强度数据后启用；
- **安全运行时**（→P2 智能体）：蓝图缺口清单将作为智能体"主动建议下一步"的结构化输入。

## 四、权限与审计

| 操作 | 权限 | 审计事件 |
| --- | --- | --- |
| 解析/更新蓝图 | 项目写权限（can_write_project） | `blueprint_parse` |
| 查看蓝图/覆盖度 | 项目读权限 | — |
| 修正节点/边（作废、描述） | 项目写权限 | `blueprint_node_patch` / `blueprint_edge_patch` |

## 五、验证

- Rust 集成测试 3 项：规则解析与覆盖度联动（笔记审核→抽取→覆盖度上升）、
  冲突优先级消解（纪要覆盖计划书、作废不可恢复冲突）、幂等与权限边界（重复解析零新增、越权 403）；
- 迁移测试：alembic 0015（SQLite/PostgreSQL 双方言）+ Rust 运行时 ensure 路径（schema v5）；
- 演示路径：图谱页「知识蓝图」页签 → 解析计划书 → 查看覆盖度与虚线待实证节点 →
  审核一条同名笔记 → 覆盖度上升、节点实心化。

## 六、已知边界（诚实性）

- v1 覆盖判定为精确匹配（类型+规范名），语义近似的覆盖（如"细胞活力检测"≈"CCK-8 检测"）需要 LLM 辅助对齐，列为 v2；
- 边的覆盖度未单独计算（当前以节点覆盖近似项目完成度）；
- 规则抽取模式只产生节点不产生关系，边依赖 AI 解析；两种模式均留痕，不混淆口径。
