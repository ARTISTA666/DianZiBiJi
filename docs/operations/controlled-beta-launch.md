# 受控试运行上线策略

本项目先以“受控试运行”获得真实科研用户反馈，再根据反馈迭代。确认性人工评审暂不作为首批上线阻塞项，但它仍保留为后续科研质量验证和论文质量声明的门禁。

## 上线边界

- 首批用户只使用真实生产配置、TLS 反向代理和持久化数据库/文件存储。
- 系统继续展示证据状态、引用校验和降级原因；没有项目证据的回答不能被表述为项目事实。
- 盲评和正式人工评审接口保留，但不会伪造已完成的人工质量结论。
- 试运行阶段只允许小规模、可回滚的用户范围；上线后持续观察错误率、延迟、存储增长、AI 费用和反馈。

## 发布门禁

```bash
backend/.venv/bin/python scripts/controlled_beta_gate.py
```

该门禁不检查确认性人工评审，但仍要求：内部门禁、生产配置、真实 TLS 证据、异地加密备份证据、Rust `/health` 与 `/ready`、Docker Compose 配置全部通过。当前开发环境的生产配置快照是 `skipped_non_production`，因此不能直接宣称已具备公网发布条件。

## 上线后反馈闭环

1. 每周汇总问答日志、错误日志、引用审计失败和用户反馈。
2. 优先修复数据泄露/越权、错误引用、服务不可用和高成本问题。
3. 再优化检索、提示词、界面和性能；每次变更重新跑对应运行时检查。
4. 反馈样本达到可用规模后，再启动独立人工评审和正式质量报告。

## 回滚条件

出现敏感数据外泄、权限绕过、数据库/文件恢复失败、连续服务不可用、引用审计异常激增或 AI 成本失控时，立即停止新增用户并回滚到上一镜像与数据库恢复点。
