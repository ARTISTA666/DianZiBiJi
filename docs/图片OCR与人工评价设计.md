# 图片 OCR 与人工评价设计

## 图片 OCR

系统支持 PNG、JPG、JPEG、BMP、GIF、TIFF 和 WebP 图片。处理流程如下：

1. 用户上传图片，系统保存原文件和 SHA-256 哈希。
2. Tesseract 按 `OCR_LANGUAGES` 配置识别文字，业务默认使用 `chi_sim+eng`，目标输入为中文和英文实验记录、试剂标签及仪器截图。
3. 系统将原始识别文本、识别方式、字符数、文件哈希和操作人保存到 `file_ocr_results`。
4. 审核人对照原图修正文字，点击“确认校对并签名”。系统保留原文，另存修正文本、确认人和确认时间。
5. 图片资料入库时，系统只读取最新且已确认的校对文本。没有确认记录时，RAG 入库会被拒绝。
6. 提取与确认分别记录 `extract_file_text` 和 `confirm_file_ocr` 审计动作。

OCR 结果可能受图片清晰度、倾斜、手写字体和复杂表格影响。系统不把未校对的 OCR 输出视为已审核实验事实。

OCR 效果使用独立标准文本计算字符错误率，不使用系统自己的输出作为答案。评价脚本为 `scripts/evaluate_ocr.py`，会保存输入文件哈希、编辑距离、微平均和宏平均字符错误率，以及数字识别结果。详细规则见 `docs/experiments/ocr-evaluation-protocol-v1.md`。

外部真实手写压力测试已完成：10 页 RUKOPYS 大学考试扫描件的 Tesseract 原图微平均 CER 为 75.72%，固定 Otsu 方案留出集 CER 为 78.58%；未微调 HTRflow/TrOCR 在同开发集和留出集上的 CER 分别为 107.02% 和 111.51%。RUKOPYS 是乌克兰语手写文本识别数据集，该实验单独使用 `ukr`，与业务默认的 `chi_sim+eng` 在语种、文字系统和材料领域上均不一致。因此这些数字只用于检验复杂异域手写输入下系统是否保留机器原文、要求人工确认并阻止未确认文本入库，不是中文或英文实验记录的准确率。详细边界见 `docs/experiments/ocr-language-scope-2026-07-15.md`。

运行验收已证明未确认图片无法进入 RAG，确认后向量分块使用校正文，详见 `docs/experiments/ocr-runtime-e2e-2026-07-12.md`。

## 人工评价

人工评价针对每条 RAG 回答记录三个指标：

- 准确性：回答中的事实是否与证据一致。
- 可追溯性：关键结论能否从页面所列证据中找到。
- 综合评分：1 至 5 分。

独立评价账号只能调用专用盲评接口。后端使用 HMAC 生成无法从页面反推日志号的批次编号和回答编号。接口不返回检索模式、日志号、模型名、响应时间、图谱命中数或运行顺序。回答中的 `[S]` 和 `[G]` 标记统一转换为 `[E]`，资料片段和关系证据也使用同一编号方式展示。

评价表以“回答记录 + 评价人”为唯一键。两名评价者可以对同一回答分别保存结果，不会相互覆盖。每条评价同时保存评价协议：独立页面提交记为 `method_masked`，管理视图提交记为 `unblinded`。评价提交后不允许再次改写；管理端汇总评价数、评价人数、准确性一致率、可追溯一致率和 Cohen’s kappa。

人工评价使用独立的 `can_evaluate` 权限。评价人不能查看原始问答日志、模式统计或实验导出，也不能初始化知识库、运行新实验、审核资料或修改实验记录。

项目管理者不能通过独立盲评接口提交评分。正式汇总脚本只接受 `method_masked` 记录，混入管理复核记录时直接停止。

系统只能提供评价工具，不能代替评价人作出判断。论文中的人工评价结果必须由真实评价人完成，不能由程序或语言模型自动填写。
