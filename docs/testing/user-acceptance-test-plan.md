# 用户级验收测试项目

## 目的与边界

本项目验证科研人员是否能在接近真实课题组协作的条件下完成工作，而不以接口成功、单组件渲染或预置演示数据替代用户体验。测试对象是“智能电子实验笔记系统”的生产构建与隔离数据栈。

自动化验证可证明重复性和权限边界；它不能替代真实用户对可理解性、耗时和信任感的反馈。任何人工结论均须由实际参与者填写观察记录后才可报告。

## 人员与场景

| 人员 | 真实职责 | 关键任务 |
| --- | --- | --- |
| 项目负责人 | 建立课题、分配协作权限 | 创建项目；邀请成员和审核人；核对最小权限 |
| 实验记录员 | 完成日常实验记录 | 新建、保存、修订、提交笔记；根据意见重提 |
| 审核人 | 核查可追溯性和完整性 | 查看待审记录；退回并写出可执行意见；批准修订版 |
| 只读成员 | 使用已批准知识但不改变原始记录 | 查阅笔记；确认没有写入、作废或项目管理入口 |
| 独立评价人 | 只评价方法隐藏后的结果 | 仅进入盲评工作区，不能查看项目原始内容 |

## 自动化验收套件

| 用户旅程 | 自动化用例 | 可接受结果 |
| --- | --- | --- |
| 创建—记录—退回—修订—批准 | `项目负责人、记录员和审核人完成退回修订审批闭环` | 修订版为 v2；两条审批意见可追溯；状态为已审核 |
| 多角色 AI 协作 | `多角色完成 AI 资料、图谱、问答与报告协作闭环` | 记录员上传资料并提取图谱；审核人完成资料审核与 OCR 校对；负责人初始化并入库；记录员完成有来源的 RAG 问答和报告生成 |
| 最小权限 | `只读成员只能查阅，不能看到写入或项目管理操作` | 无新建、编辑、提交、作废和设置入口；直接访问设置页也被拒绝 |
| OCR 到问答与对照实验 | `图片 OCR、人工校对、入库、问答和五方法实验形成闭环` | 未确认 OCR 文本不能入库；确认后可检索并完成五方法批次 |
| 独立评价 | `独立评价人只能在盲评页面提交评价` | 评价人没有笔记及资料入口，能够提交盲评 |
| 管理治理 | `系统管理员完成账号、小组和审计闭环` | 账号、小组、审计记录和评价人隔离均可在界面完成 |

## 真实用户试用

招募至少 6 人：2 名有审核职责的课题组成员、3 名日常记录实验的成员、1 名只读协作成员。不要让系统开发者充当被试。每位参与者使用单独测试账号，在不提供逐步指导的情况下完成以下任务：

1. 建立一个含简短目标的测试项目，邀请一位记录员和一位审核人。
2. 记录员录入一次真实但脱敏的实验过程，保存草稿后提交审核。
3. 审核人退回记录，给出一项可执行的修订要求；记录员完成修订并再次提交；审核人批准。
4. 上传一份真实但允许使用的仪器截图或实验附件，核对提取文本，只在确认后入库，并通过问答定位其来源。
5. 只读成员查找已批准记录，确认其不能发起写入或查看管理设置。
6. 独立评价人只在盲评页完成一次评分，核对看不到项目原始笔记。

记录员、审核人和只读成员在每项任务后填写 [用户试用观察记录表](user-test-observation-template.md)。主持人只记录事实，不替参与者完成操作。

## 判定与发布门槛

自动化套件必须 100% 通过。人工试用只有在以下全部满足时才可标为“用户验收通过”：

- 每类角色至少 2 名有效参与者（只读成员至少 1 名）；
- 关键任务 1、2、3、5、6 的无协助完成率至少 80%；
- 没有未解决的 P0/P1 权限、数据丢失、错误审批或错误入库问题；
- 每个失败任务有复现步骤、截图/时间、严重度、责任人和处理状态；
- AI 问答结果须由参与者按来源可追溯性和正确性单独评分，不能把“接口返回”当作回答质量通过。

在真实参与者完成前，报告只能表述为“自动化用户旅程通过、人工试用待执行”，不得声称已经验证真实用户满意度或 AI 效果。
